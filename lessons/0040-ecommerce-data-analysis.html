🎯 本课目标：用 UCI Online Retail 真实数据集，讲清GMV / 客单价 / 复购率 / RFM 四个电商核心指标的口径定义和业务含义。重点不是「会跑 pandas」，而是能读懂数据、核验 AI 结果——知道一个指标该怎么算、算出来的数字对不对、背后说明什么业务问题。

一、为什么「指标口径」比代码更重要？

31 课我们已经说过「指标口径先于代码」。到了电商实战，这句话的分量更重——同一个 GMV，不同口径算出来的数字可以差 30% 以上。

📌 真实场景：面试官问你"这家电商的复购率是多少？" 你说"68%"。面试官追问："口径是什么？" 你说"不知道，Agent 跑出来的"。对话结束。
但如果你说"排除退货、去掉 CustomerID 缺失的行、按 InvoiceNo 去重后是 68%——不过要注意这个数据集有约 25% 的 CustomerID 缺失，实际复购率可能更高"。这就是数分能力。

二、四个核心指标：口径 + 业务含义

① GMV（总成交金额）

维度说明
定义GMV = Σ(Quantity × UnitPrice)，即所有成交订单的金额总和
口径陷阱退货单（InvoiceNo 以 C 开头）的 Quantity 是负数——不剔除的话 GMV 会被拉低
业务含义衡量平台/店铺的流水规模，但不等于利润（未扣成本）
常见变体净 GMV = GMV - 退货金额；有效 GMV = 只算已完成订单
 
# GMV 计算：必须先排除退货单
df["Revenue"] = df["Quantity"] * df["UnitPrice"]
# 排除退货：InvoiceNo 以 C 开头的行
valid = df[~df["InvoiceNo"].astype(str).str.startswith("C")]
gmv = valid["Revenue"].sum()   # ~ 818万（UK为主）

# 如果不排除退货会怎样？
gmv_with_returns = df["Revenue"].sum()  # ~ 773万，差了约 45万
⚠️ 面试考点："GMV 是多少？" 这个问题看似简单，但不给口径的数字没有意义。面试时主动说"我用的口径是 XX"，是加分项。

② 客单价（Average Order Value）

维度说明
定义客单价 = GMV / 订单数（注意：是订单数，不是客户数）
口径陷阱一个 InvoiceNo 可能包含多行商品——必须先按 InvoiceNo 汇总金额，再除以去重后的订单数
业务含义衡量每笔交易的平均消费水平，指导定价策略和促销设计
常见错误用 df["Revenue"].mean()——这是行均值，不是订单均值（一个订单有多行）
 
# ✅ 正确：先按订单汇总，再算平均
order_totals = valid.groupby("InvoiceNo")["Revenue"].sum()
aov = order_totals.mean()

# ❌ 错误：直接对行求平均（把一个订单的多行拆开算了）
aov_wrong = valid["Revenue"].mean()  # 结果偏小

③ 复购率

维度说明
定义复购率 = 下过 2 单及以上的客户数 / 总客户数 × 100%
口径陷阱CustomerID 约 25% 缺失——这些行必须剔除，否则分母虚高、复购率偏低
业务含义衡量客户粘性——复购率越高，说明产品/服务留得住人
行业参考电商复购率一般在 30%-70% 之间；快消品偏高，耐用品偏低
 
# 复购率计算
valid_customers = valid.dropna(subset=["CustomerID"])
orders_per_customer = valid_customers.groupby("CustomerID")["InvoiceNo"].nunique()
total = len(orders_per_customer)
repeat = len(orders_per_customer[orders_per_customer >= 2])
repeat_rate = repeat / total * 100   # ~ 68%（UK 数据）

# 如果不排除 CustomerID 缺失的行会怎样？
all_customers = valid.groupby("InvoiceNo").first()  # 错误：不是按客户聚合
# 结果会完全不同——这就是口径的重要性

④ RFM 模型

维度定义业务含义
R（Recency）客户最后一次购买距今的天数越近越活跃
F（Frequency）客户的总订单数（去重 InvoiceNo）越多越忠诚
M（Monetary）客户的总消费金额贡献越大

RFM 的核心思想：用三个维度把客户分成不同群体，针对不同群体制定不同策略（如对高价值低活跃的客户发挽留券）。

# RFM 计算（以数据集最后一天为基准日）
import datetime as dt

snapshot = valid["InvoiceDate"].max() + dt.timedelta(days=1)

rfm = valid.groupby("CustomerID").agg({
    "InvoiceDate": lambda x: (snapshot - x.max()).days,   # R: 最后购买距今天数
    "InvoiceNo":   "nunique",                             # F: 订单数
    "Revenue":     "sum"                                   # M: 总金额
})
rfm.columns = ["Recency", "Frequency", "Monetary"]

# 简单分箱：用中位数二分
rfm["R_Score"] = (rfm["Recency"] <= rfm["Recency"].median()).astype(int)
rfm["F_Score"] = (rfm["Frequency"] >= rfm["Frequency"].median()).astype(int)
rfm["M_Score"] = (rfm["Monetary"] >= rfm["Monetary"].median()).astype(int)
📌 RFM 的业务价值：不是算完三个数就结束了——关键是用 RFM 分群后采取行动。比如 R 高（很久没来）+ F 高（以前常买）= 沉睡客户 → 发召回优惠券。这才是 RFM 被称为"电商最经典客户分层模型"的原因。

三、漏斗与转化思维

电商分析不只是算指标，还要看转化路径：浏览 → 加购 → 下单 → 付款 → 复购。每一步都有流失，找到流失最大的环节就是业务突破口。

# 漏斗分析思路（本数据集的简化版）
# 原始数据没有浏览/加购数据，但可以用现有字段构造一个简单漏斗：

# 1. 全部下单客户（有 InvoiceNo 的）
all_customers = valid["CustomerID"].dropna().nunique()

# 2. 付费客户（排除金额为 0 的订单）
paid = valid[valid["Revenue"] > 0]
paid_customers = paid["CustomerID"].dropna().nunique()

# 3. 复购客户（2 单及以上）
repeat_customers = orders_per_customer[orders_per_customer >= 2].shape[0]

# 转化率
print(f"下单→付费: {paid_customers/all_customers:.1%}")
print(f"付费→复购: {repeat_customers/paid_customers:.1%}")
💡 漏斗思维的本质：不是数据有没有的问题，而是「在哪个环节丢了人、为什么丢」的问题。即使数据集字段有限，也要养成"看转化"的习惯——这是面试中"业务理解"的核心展示点。

四、核验 AI 结果：你怎么判断 Agent 算对了？

34 课学的 verify 核验卡口，在电商分析中怎么用？

  1. 交叉验证：Agent 算了一个 GMV，你自己用不同方式复算（比如按月汇总再求和 vs 直接求和，结果应该一样）
  2. 量级校验：54万行数据，GMV 在百万量级才合理——如果 Agent 返回几十万或几千万，肯定哪里算错了
  3. 边界检查：复购率不可能超过 100%；客单价不可能是负数；客户数不可能超过总行数
  4. 口径一致性：Agent 这次算 GMV 排除了退货，下次算也必须排除——口径不一致的数字不能放在一起比较
# 你自己的快速核验脚本（不依赖 Agent）
df = load_data()
valid = df[~df["InvoiceNo"].astype(str).str.startswith("C")]
valid["Rev"] = valid["Quantity"] * valid["UnitPrice"]

# 快速看分布
print(valid["Rev"].describe())   # mean/std/min/max
print(valid["Rev"].sum())       # 你心中的 GMV
print(valid["CustomerID"].dropna().nunique())  # 有效客户数

五、动手任务：自己算一次复购率并核对口径

🎯 任务（15 分钟）：用 UCI Online Retail 数据集，自己写 pandas 代码算一次复购率。要求：
  1. 先定口径：排除退货？排除 CustomerID 缺失？怎么定义"一单"？
  2. 写代码计算，把每一步的中间结果打印出来（总客户数、复购客户数、复购率）
  3. 用 39 课的 calc_repeat_rate 工具跑一遍，比对结果
  4. 如果结果不一致，找到口径差异——这比算对本身更有价值

提示：你可能会发现 calc_repeat_rate 和你自己的代码算出来差几个百分点。别慌，大概率是 CustomerID 缺失的处理方式不同——找到差异原因就是本任务的核心收获。

本课学了什么

  • ✅ GMV：= Quantity × UnitPrice，必须排除退货单（InvoiceNo 以 C 开头），衡量流水规模
  • ✅ 客单价：= GMV / 订单数（不是行均值！），衡量每单消费水平
  • ✅ 复购率：= 下过 2+ 单的客户 / 总客户，衡量客户粘性，注意 CustomerID 缺失的影响
  • ✅ RFM：Recency + Frequency + Monetary，经典客户分层模型，核心是分群后采取行动
  • ✅ 核验能力：交叉验证、量级校验、边界检查、口径一致性——能判断 AI 算的对不对

🤔 小测

Agent 跑了一个 RFM 分析，输出"平均 Recency 为 92 天，平均 Frequency 为 4.2 单，平均 Monetary 为 2037"。你怎么核验这个结果？

  1. 直接看输出是否是三个数字——是的话就对了
  2. 自己用 pandas 分别算 R/F/M 的均值，与 Agent 结果比对
  3. 问 Agent 这三个数字的口径是什么，看它能不能回答
  4. B 和 C 都要做——先自己算一遍，再追问口径
点击展开答案与解析
答案：D（B 和 C 都要做）。光看格式没用（A 错）。B 是硬核验——自己算一遍就知道数字对不对；C 是口径核验——确认 Agent 用的口径（比如有没有排除退货、CustomerID 缺失怎么处理）是否与你的预期一致。数字对 + 口径对 = 结果可信。这是 34 课 verify 核验卡口在电商分析中的具体应用。
