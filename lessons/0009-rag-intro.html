📚 RAG：让 AI 基于你的文档回答

第 9 课 · 2026-07-06 · 概念 + 代码

🎯 增量胜利：学完这课，你就理解了为什么让 AI 「先查资料再回答」比「直接回答」靠谱得多，以及用 10 行代码就能实现这个能力。

回顾：上节课的问题

在第 5 课，我们写了一个读文件总结脚本。那个脚本有一个明显的天花板：

  • 把整份文档当 prompt 发给 AI
  • 如果文档太长（超过模型的上下文窗口），会报错或被截断
  • 如果只问文档里的某个细节，AI 还是要处理整份文档——浪费 token，浪费钱

更糟糕的场景更常见：你手头有几十份文档或者一个公司的知识库（产品手册、合同模板、制度文件），你不可能把全部内容塞进一个 prompt。这就是 RAG 要解决的问题。

💡 RAG 的全称

Retrieval-Augmented Generation = 检索增强生成。

核心思想很简单：回答问题之前，先到文档库里找相关信息，把找到的内容塞进 prompt 里，再让 AI 回答。

RAG 的三步流程

RAG 其实就三步，非常直观：

┌──────────┐ ┌──────────┐ ┌──────────┐
│ 1. 检索 │ → │ 2. 增强 │ → │ 3. 生成 │
│ 找相关文档 │ │ 拼进prompt│ │ AI 作答 │
└──────────┘ └──────────┘ └──────────┘
步骤做什么大白话
1. 检索（Retrieve） 从文档库里找到与问题最相关的几段 「关于这个问题的资料在文档的哪儿？」
2. 增强（Augment） 把检索到的段落 + 原问题拼成一个 prompt 「给你三段参考资料，请基于它们回答以下问题」
3. 生成（Generate） 把拼好的 prompt 发给 DeepSeek API 第 3 课学过的那一行 client.chat.completions.create()

可视化理解

对比一下「纯模型回答」和「RAG 回答」：

纯模型回答RAG 回答
信息来源 模型训练时的记忆（可能过时） 你提供的实时文档
能回答 「什么是变压器？」（常识） 「咱们公司去年的营收是多少？」（内部信息）
幻觉风险 高——模型可能「编」答案 低——基于你的文档说话
知识更新 要重新训练模型（贵） 换一个文档即可（便宜）
适用场景 闲聊、常识问答、翻译、写作 客服问答、企业内部搜索、合同审查

10 行核心代码

下面是最简 RAG 的实现。先看代码，再看逐行解释。

from openai import OpenAI
import jieba                            # ← 用于分词

client = OpenAI(api_key="sk-你的密钥", base_url="https://api.deepseek.com")

# —— 1. 准备文档库（三句话当做三篇「文档」） ——
docs = [
    "公司2024年营收为12.5亿元，同比增长18%。",
    "公司主营业务为AI软件开发，客户包括金融和医疗行业。",
    "2025年Q1净利润为3200万元，毛利率65%。"
]

# —— 2. 用户提问 ——
question = "公司去年营收是多少？"

# —— 3. 检索：用关键词匹配找相关文档 ——
words = set(jieba.lcut(question))      # 把问题切成词
scores = []
for i, doc in enumerate(docs):
    doc_words = set(jieba.lcut(doc))
    overlap = len(words & doc_words)    # 交集大小 = 相关度
    scores.append((overlap, i))
scores.sort(reverse=True)
top_docs = [docs[i] for _, i in scores[:2]]  # 取前 2 条

# —— 4. 增强：构造 prompt ——
context = "\n".join(top_docs)
prompt = f"""基于以下资料回答问题：

{context}

问题：{question}
请用中文简洁回答。如果资料中没有相关信息，请说「资料中未找到相关信息」"""

# —— 5. 生成：调 API ——
response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": prompt}]
)
print(response.choices[0].message.content)

逐行解释

代码什么意思
import jieba 引入分词库。中文不按空格分词，需要这个库把「公司去年营收是多少？」切成「公司/去年/营收/是/多少」。jieba 是最流行的中文分词库
set(jieba.lcut(question)) 把句子分词后转成集合（set），方便做交集运算
len(words & doc_words) 计算问题和文档有多少个相同的词。词重叠越多 ≈ 越相关。这就是最简单的「检索」——基于关键词匹配
scores.sort(reverse=True) 按相关度从高到低排序，取前 2 条最相关的文档
context = "\n".join(top_docs) 把检索到的文档拼接成一段「参考资料」
f"""基于以下资料回答问题：\n{context}\n问题：{question}""" 增强（Augment）——把资料和问题拼成一段完整的 prompt，明确告诉 AI「基于资料回答」
if not found → 说未找到 prompt 里加了这个指令，AI 就不会在资料没相关内容时瞎编
⚡ 注意：这里的关键词匹配检索只是演示原理。生产环境中，RAG 用的是向量检索（把文字转成数学向量，计算语义相似度），能匹配「虽然用词不同但意思相近」的内容。那是进阶话题，以后会讲。

运行前的准备

  1. 安装 jieba：pip install jieba
  2. 把 api_key 改成你的 DeepSeek API Key
  3. 运行 python rag_demo.py

试试修改 docs 里的内容，换成你自己的文档片段。再改改问题，看 AI 的回答是否基于你给的资料。

RAG 和你的工作有什么关系？

作为项目助理，你可能经常需要：

  • 查制度：公司几十份制度文件——不用翻，直接问「病假怎么请？」RAG 帮你找到对应条款
  • 审合同：合同模板库——「我们合同里的违约金上限是多少？」RAG 找到对应条款
  • 写周报：翻看过去几周的周报——「上周项目 A 的进展是什么？」RAG 从周报库中提取
  • 做培训：产品手册——「V3.2 版新增了什么功能？」RAG 基于手册回答

这些都是 RAG 可以自动化的事。之前你说「AI 不知道我们公司内部的事」——有了 RAG，它就能知道了。

RAG 中的「增强（Augment）」步骤具体做了什么？

  1. 用更多 GPU 加快 AI 的推理速度
