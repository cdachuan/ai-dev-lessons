⏰ 搭一个定时任务脚本

第 0015 课 · 实践课 工具篇·五

🎯 增量胜利：学完这课，你就理解怎么让脚本「自己定时跑」——每天早上 8 点自动生成日报、每周五自动出周报，不用你手动点。这正是 Hermes 里 cron 任务的原理。

场景：让工具自己按点干活

前几课的脚本都要你手动敲命令运行。但很多活儿是周期性的：

  • 每天早上 8 点，把昨天的进度汇总成日报
  • 每周五下午，把一周任务表合并成周报
  • 每小时检查一次某个文件夹有没有新文件

这些不该靠你记着去点。让操作系统的「定时器」来触发脚本，才是自动化的完整闭环。

两层概念：脚本 vs 调度器

角色负责什么
脚本（你写的 .py）干活——读数据、调 API、生成结果
调度器（系统提供）掐点——到时间了，替你把脚本运行一遍

你已经在用调度器了——Hermes 里每天早上 8 点给你推课的那个 cron 任务，就是调度器在掐点触发。

做法一：脚本自己带定时（schedule 库）

最简单的入门方式：让脚本自己转着圈等时间到。安装：pip install schedule

import schedule
import time

def daily_report():
    print("正在生成日报...")
    # 这里放你前面写的日报脚本逻辑

# 每天 08:00 跑一次
schedule.every().day.at("08:00").do(daily_report)

# 每周五 17:00 跑一次
schedule.every().friday.at("17:00").do(daily_report)

# 保持运行，每 60 秒检查一次「时间到了没」
while True:
    schedule.run_pending()
    time.sleep(60)
⚠️ 局限：这个 while True 循环得一直开着脚本才会触发。关了电脑或关了终端就停了。适合学原理、跑临时任务，不适合真正的长期自动化。

做法二：交给系统调度器（推荐）

真正的自动化，是把脚本注册给操作系统，由系统在后台掐点跑——你不用一直开着。

系统调度器
Windows任务计划程序（Task Scheduler）
Mac / Linuxcron
Hermes内置 cron（就是给你推课的那个）

以 Windows 为例，在「任务计划程序」里新建任务，设定：

  • 触发器：每天 08:00
  • 操作：运行 python D:\脚本\daily_report.py

设好后，哪怕你没开终端，到点系统自己就把脚本跑了。这才是「设一次，永久自动」。

💡 联系你的日常：你天天用的 Hermes「每天 8 点推课」「Hindsight 看门狗每小时巡检」，本质就是做法二——脚本 + 系统级调度器。你早就在享受定时任务的成果了，这课只是把幕后原理讲透。

本课学了什么

  • ✅ 区分「脚本干活」和「调度器掐点」两层角色
  • ✅ 用 schedule 库让脚本自带定时（学原理用）
  • ✅ 用系统调度器（Windows 任务计划 / cron）实现真正的长期自动化
  • ✅ 理解 Hermes cron 推课、看门狗巡检的底层原理

🤔 小测

你想让日报脚本「每天早上 8 点自动跑，哪怕没开终端也能触发」，最合适的做法是？

  1. schedule 库 + while True 循环，终端一直开着
  2. 注册到系统调度器（Windows 任务计划 / cron），交给系统后台掐点
  3. 设个闹钟，响了手动运行
  4. 让脚本每秒都跑一遍
