📚 第 2 课 · 什么是 API？

2026-06-30 · 阅读约 5 分钟 · 术语表

一句话讲清

API（Application Programming Interface，应用程序接口） 是两个程序之间的「传话筒」。
就像你去餐厅——你告诉服务员你要什么，服务员去后厨通知厨师，再把做好的菜端回来给你。
你不必亲自进厨房。

对你有什么用？
赫默帮你「点了菜」。学会自己调 API = 你自己当服务员，想什么时候点菜、点什么菜都行。这就是自动化的起点——你写一个脚本，让 AI 模型批量处理 100 个文件，而不是一个个手动粘贴到赫默里。

服务员、厨房、你的关系

🙋 你（客户端）
告诉服务员你想要什么
→
🧑‍🍳 API（服务员）
把指令传给厨房，把菜端回来
→
🔥 模型（厨房）
收到指令，开始工作，产出结果

套用到你每天用的赫默上：

角色你的日常类 比
你在赫默对话框里打字提问顾客看菜单、点菜
赫默把你的输入转成 API 请求并发送服务员下单
DeepSeek API接收请求、传给模型、返回结果服务员与厨房的通道
AI 模型阅读你的输入，逐字生成回复后厨炒菜
回复赫默把结果显示给你看服务员端菜上桌

API 调用长什么样？

API 不是什么高深技术——它本质上就是一个 URL 地址 + 一段消息。
你的程序往这个地址发一条消息，对方服务器就会回复你。

拿 DeepSeek 来举例，一次 API 调用大概长这样：

POST https://api.deepseek.com/chat/completions
Authorization: Bearer sk-your-api-key-here
Content-Type: application/json

{
  "model": "deepseek-chat",
  "messages": [
    {"role": "user", "content": "用一句话解释什么是 API"}
  ]
}

回复（简化后）：

{
  "choices": [
    {
      "message": {
        "content": "API 是两个程序之间的传话筒，让它们能互相通信。"
      }
    }
  ]
}
💡 关键洞察：上面这段代码就是你每次在赫默里打字时，赫默替你在背后做的事。看懂这段 JSON 格式的请求，你就看懂了 AI 应用的核心通信机制。

JSON 只是一种数据格式，像表格一样有「键」和「值」——比如 "model" 是键，"deepseek-chat" 是值。你不需要记住括号怎么打，只需要理解：你在发一条结构化的消息给 AI。

为什么不用赫默，要自己调 API？

这是一个很自然的问题。答案：赫默是给人用的，API 是给程序用的。

场景用赫默自己调 API
问一个问题✅ 打字就行❌ 需要写代码
批量处理 100 个文件❌ 手动粘贴 100 次✅ 一个脚本全自动
每天定时生成报表❌ 每天手动操作✅ 设个定时任务
和其他系统对接❌ 没法集成✅ 嵌入你的工具链

你的元目标是「从只会用赫默聊天进阶为能自己搭 AI 小工具的人」——自己调 API 就是跨过这道门槛的第一步。

术语：API Key

上面代码里那个 sk-your-api-key-here 就是 API 密钥。
它像你的身份证 + 银行卡密码——证明是你本人在调用，DeepSeek 按这个来计费。
⚠️ 不要把 API Key 发到公开地方（GitHub、群里），别人拿了就能用你的额度。
