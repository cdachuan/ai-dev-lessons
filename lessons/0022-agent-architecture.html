🤖 Agent 入门：从脚本到智能体

第 0022 课 · 创造篇·一 概念课

🎯 本课目标：理解 Agent 到底是什么，它和脚本有什么本质区别。你天天在用 Hermes——现在该搞懂它为什么能自己干活了。这是 Phase 4「创造篇」的第一步：从「会写脚本」升级到「理解智能体」。

你已经在用 Agent 了

过去 21 课里，你写了 pandas 代码、画了图、调了 API。每次都是你规定好每一步，电脑照着做——这就是脚本。

但你也发现了另一件事：你跟 Hermes 说「帮我分析这些台区的用电异常」，它就自己读文件、算指标、判断异常、写结论，中间不用你插手。这不是脚本——这是 Agent（智能体）。

💡 一句话区分：脚本是「你规定每一步做什么」，Agent 是「你给目标，它自己决定怎么做」。

脚本 vs 智能体：一个对比例子

同一个任务：分析本月用电异常台区。

脚本方式

你需要自己想清楚每一步，然后写成代码：

# 你规定每一步
# 第1步：读数据
df = pd.read_csv('用电数据.csv')

# 第2步：算波动
df['波动'] = df.groupby('台区')['电量'].std()

# 第3步：筛选异常
异常 = df[df['波动'] > 阈值]

# 第4步：调API让AI写结论
结论 = call_ai(f"根据以下异常数据写结论：{异常}")

# 第5步：输出
print(结论)

每一步都是你设计的。换个任务——比如「找出电量突增的台区」——你得重新写一套流程。

Agent 方式

你只给目标和权限：

"帮我分析本月哪些台区用电异常，给出报告。数据在 D:/用电数据.csv。"

Agent 自己决定怎么做：它可能先读数据看结构，发现需要算波动，算完发现某些台区数据缺失，自己想办法补，然后判断哪些算异常，画张图，最后写报告。中间这些决策，没有一个是你规定的。

💡 核心区别：脚本 = 你是大脑，代码是手脚；Agent = 它自己是大脑+手脚，你只管提需求。

ReAct 循环：Agent 的核心引擎

Agent 为什么能「自己决定怎么做」？因为它在一个叫 ReAct 的循环里不断运转：

阶段做什么类比
Thought（思考）分析当前状况，决定下一步做什么「数据读到了，发现有空值，得先处理」
Action（行动）调用工具执行操作调 pandas 填充空值
Observation（观察）看行动的结果，更新认知「空值填好了，数据完整了」
→ 回到 Thought根据观察结果再思考「现在可以算波动了」

这个循环不断重复，直到 Agent 认为任务完成。这就是 Hermes 每次帮你干活时背后发生的事情。

用伪代码看 ReAct 循环

# ReAct 循环的概念演示（伪代码，不可运行）

任务 = "分析本月用电异常台区，给出报告"
记忆 = []  # 对话历史 / 上下文

while True:
    # ① Thought：LLM 思考下一步
    thought = LLM.think(任务, 记忆)
    print(f"💭 {thought}")

    # 如果任务完成，退出循环
    if thought.is_done():
        break

    # ② Action：调用工具
    action = thought.next_action      # 比如 read_file / run_python
    result = 执行工具(action)         # 比如：读到数据了
    print(f"🔧 执行了 {action}")

    # ③ Observation：把结果存入记忆
    记忆.append((thought, action, result))
    print(f"👀 观察到：{result}")
    # → 回到循环顶部，带着新记忆重新思考
⚠️ 注意：这不是真实代码，是帮你理解概念的伪代码。真实的 Agent 实现要复杂得多，但核心逻辑就是这个循环。

Agent 的三个核心组件

拆开看，任何 Agent（包括 Hermes）都有三个核心部件：

组件是什么在 Hermes 里对应什么
🧠 大脑LLM（大语言模型），负责思考、推理、做决策背后的 AI 模型（如 GPT、Claude）
✋ 手脚工具 / Function Calling，让 Agent 能操作外部世界读文件、跑 Python、搜索网页、发消息
📝 记忆Context / 对话历史，记住之前做了什么对话窗口里你看到的所有内容
💡 人话版：大脑负责想，手脚负责做，记忆负责不忘。三个缺一个都不行——没大脑就是死脚本，没手脚就只能空谈，没记忆就每一步都从零开始。

为什么 Agent 比脚本强

不是所有场景都该用 Agent，但在以下情况，Agent 明显优于脚本：

  • 能处理意外：数据格式变了？脚本报错退出。Agent 发现不对，自己调整策略继续干。
  • 能自己选工具：脚本只能用你提前写好的函数。Agent 有工具箱，自己挑合适的用。
  • 能多步推理：复杂任务需要分多步、中间做判断。脚本只能按你预设的顺序走，Agent 能根据中间结果动态调整。

反过来，如果任务是固定、重复、流程明确的——比如每月固定格式跑一个报表——脚本反而更可靠、更快、更省钱。Agent 的灵活性是有代价的：更慢、更贵、结果不完全可控。

回到你的工作场景

脚本Agent
你的角色设计师：规定每一步甲方：提需求和目标
适合场景每月固定报表、批量算指标灵活分析、临时任务、需要判断的活
举例「帮我算这 10 个台区的波动」→ 写 pandas → 出结果「帮我分析哪些台区用电异常，给出报告」→ Agent 自己读数据、算指标、判断、画图、写报告
可控性高（你规定了一切）中（结果可能每次略有不同）
🔑 关键认知：Agent 不是「更好的脚本」，而是另一种东西。脚本追求精确可控，Agent 追求灵活自主。成熟的工程师两种都会用，按场景选择。

🤔 小测

同样一个任务「分析本月用电异常台区」，以下哪种方式是对的？

  1. 用脚本：自己写 pandas 代码算波动，再调 API 让 AI 写结论
  2. 用 Agent：给 Agent 目标和数据访问权限，让它自己决定怎么算、怎么判、怎么输出
  3. A 和 B 都对，只是分工不同——脚本适合固定重复任务，Agent 适合灵活多变的任务
  4. 必须用 Agent，Agent 一定比脚本强
