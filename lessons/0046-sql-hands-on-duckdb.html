二、duckdb：零安装的 SQL 练习场

pip install duckdb 即可。它是「进程内」分析型数据库——不装服务、不起端口，直接对 CSV/DataFrame 跑 SQL，而且比 pandas 快。

import duckdb
df = duckdb.read_csv('online_retail_2010_2011.csv', header=True)

# 你的第一条 SQL：先摸清盘子（对应 39 课的 profile）
duckdb.sql("""
  SELECT COUNT(*) AS n,
         MIN(InvoiceDate) AS first_order,
         MAX(InvoiceDate) AS last_order
  FROM df
""").show()
--> 541909 行，2010-12-01 ~ 2011-12-09
📌 阅读顺序：SELECT 要什么列 → FROM 哪张表 → WHERE 过滤行 → GROUP BY 分组 → ORDER BY 排序 → LIMIT 取前几。每个查询都按这个顺序读，再复杂的 SQL 也不慌。

三、逐个过关：从 GROUP BY 到 JOIN 到窗口

3.1 聚合：国家 GMV Top3

duckdb.sql("""
  SELECT Country,
         ROUND(SUM(Quantity * UnitPrice), 0) AS gmv
  FROM df
  WHERE CustomerID IS NOT NULL AND UnitPrice > 0   -- 清洗口径，和 39 课一致
  GROUP BY Country
  ORDER BY gmv DESC
  LIMIT 3
""").show()
-- United Kingdom  6767873
-- Netherlands       284662
-- EIRE              250285

对照 39 课：和 ecommerce_toolkit.groupby_agg 算出来的一模一样。SQL 的 GROUP BY = pandas 的 groupby，同一个概念两套语法。

3.2 JOIN：两张表拼起来

真实工作里数据分居多表（订单表 + 客户表 + 商品表）。JOIN 按 key 把它们横向拼接：

-- 假设有 orders 和 customers 两张表
SELECT o.InvoiceNo, c.Segment, SUM(o.Quantity * o.UnitPrice) AS gmv
FROM orders o
JOIN customers c ON o.CustomerID = c.CustomerID   -- 按 key 对上
GROUP BY o.InvoiceNo, c.Segment

面试高频坑：INNER JOIN 只留两边都有的行；LEFT JOIN 保左表全量、右边填 NULL。join 后行数暴涨/骤降是新手第一天就会犯的错——join 前后各数一遍行数。

3.3 窗口函数初见：不折叠行的「分组计算」

GROUP BY 把很多行折成一行；窗口函数保留每一行，只是在旁边多一列计算结果。这是 SQL 入门和进阶的分水岭，下一课专练，这里先见个面：

WITH m AS (
  SELECT date_trunc('month', InvoiceDate) AS mo,
         SUM(Quantity * UnitPrice) AS rev
  FROM df WHERE CustomerID IS NOT NULL AND UnitPrice > 0
  GROUP BY 1
)
SELECT mo, ROUND(rev, 0) AS rev,
       ROUND(rev / LAG(rev) OVER (ORDER BY mo) - 1, 3) AS mom  -- 环比
FROM m LIMIT 5
-- 2010-12  554604   (首月无环比)
-- 2011-01  475074   -0.143
-- 2011-02  436546   -0.081
-- 2011-03  579965   +0.329

LAG(rev) OVER (ORDER BY mo) = 「按月份排好队，把我上个月的 rev 放到我这行」。一行 SQL 算出环比——窗口函数的威力。

四、SQL 与 pandas 互通

duckdb 最妙的一点：DataFrame 和 SQL 互通。SQL 取数 → pandas 出图 → SQL 再汇总，各用所长：

import pandas as pd
pdf = duckdb.sql("...复杂查询...").fetchdf()   # SQL 结果变 DataFrame
pdf.plot()                                     # pandas 画图
duckdb.sql("SELECT * FROM pdf WHERE ...")      # DataFrame 又能直接被 SQL 查

🤔 小测

用 SQL 统计「每个国家购买过的客户数」，哪条是对的？

  1. SELECT Country, COUNT(CustomerID) FROM df GROUP BY Country
  2. SELECT Country, COUNT(DISTINCT CustomerID) FROM df WHERE CustomerID IS NOT NULL GROUP BY Country
  3. SELECT Country, SUM(CustomerID) FROM df GROUP BY Country
  4. SELECT Country, COUNT(*) FROM df WHERE CustomerID IS NOT NULL GROUP BY Country

（答案见底部）

← P6 收官课 下一课：SQL 进阶模式 → 📖 术语表

小测答案：B。COUNT(DISTINCT CustomerID) 才是「去重后的客户数」——同一客户买 100 单只算 1，COUNT(*) 会算成 100 行。
A 错：没有 DISTINCT，数出来是行数不是人数；
C 错：SUM 对客户 ID 求和毫无意义；
D 错：COUNT(*) 数明细行数，一个客户多行被重复计。数人数用 DISTINCT，数行数用 COUNT(*)——SQL 第一课。
