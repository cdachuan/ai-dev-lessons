🛡️ 让工具可靠：错误处理与鲁棒性

第 0025 课 · 应用篇·五 实践课

🎯 本课目标：学会用 try/except 捕获常见错误，给脚本加上重试和日志，让它从「demo 能跑」升级成「工具能用」。

demo 能跑 ≠ 工具能用

你写过几个脚本了，demo 都能跑通，很开心。但真到同事手里用的时候：

  • 文件路径写错了，pd.read_csv() 直接崩
  • 调 DeepSeek API，网络抖了一下，脚本挂了
  • CSV 里某列名带了空格 "用电量 "，groupby('用电量') 报 KeyError

这些不是 bug，是真实世界。你的脚本必须能应对这些情况，否则只是一个 demo。

try/except：最简单的错误捕获

核心思路：try 里面放可能出错的代码，except 里面放出错后怎么办。

try:
    df = pd.read_csv('data.csv')
    print(f"读入 {len(df)} 行")
except FileNotFoundError:
    print("⚠️ 文件不存在，请检查路径")
except Exception as e:
    print(f"⚠️ 其他错误: {e}")

没有 try/except 时，程序一报错就退出。加了之后，出错也不崩，而是走你写的处理逻辑。

⚠️ 注意：except Exception 是兜底，能接住所有普通错误。但别滥用它——能精确捕获的就用精确类型（如 FileNotFoundError），Exception 只放在最后一道防线。

三种最常见的错误

类型典型场景怎么处理
文件错误路径不对、文件被占用提示用户检查路径
API 错误超时、限流、返回报错重试或降级
数据错误列名不匹配、缺失值先清洗再算

① 文件错误

try:
    df = pd.read_csv('台区数据.csv')
except FileNotFoundError:
    print("❌ 找不到台区数据.csv，请确认文件路径")
    raise  # 重新抛出，让调用者知道

② API 错误（重试一次）

import requests

for attempt in range(3):
    try:
        resp = requests.post(url, json=payload, timeout=30)
        resp.raise_for_status()
        break  # 成功就跳出
    except Exception as e:
        print(f"第{attempt+1}次失败: {e}")
        if attempt == 2:
            print("❌ 3次重试均失败，跳过此请求")

③ 数据错误（先清洗再算）

# 缺失值会导致 groupby 报错，先填 0
df['用电量'] = df['用电量'].fillna(0)

# 列名可能有空格，统一清洗
df.columns = df.columns.str.strip()

result = df.groupby('台区')['用电量'].sum()
💡 实用技巧：列名加 .str.strip() 去掉首尾空格，能解决一大半「列名明明看着对却报 KeyError」的问题。

重试机制

API 调用不稳定是常态。一个好习惯：失败后等几秒再试，最多重试 3 次。

import time

def call_api(url, payload, max_retries=3):
    for i in range(max_retries):
        try:
            resp = requests.post(url, json=payload, timeout=30)
            resp.raise_for_status()
            return resp.json()
        except Exception as e:
            print(f"第{i+1}次失败: {e}")
            if i < max_retries - 1:
                time.sleep(3)  # 等3秒再试
    return None  # 全部失败返回None

3 次都失败返回 None，调用方自己决定是跳过还是报错。重试不是万能的，但能把网络抖动这种临时问题挡掉。

日志：加个时间戳

脚本出错后，你第一个问题永远是：跑到哪一步挂的？ print 加上时间戳就行：

from datetime import datetime

def log(msg):
    ts = datetime.now().strftime('%H:%M:%S')
    print(f"[{ts}] {msg}")

log("开始读取数据...")
log("数据清洗完成，共 1200 行")
log("调用API分析...")
# [14:32:01] 开始读取数据...
# [14:32:03] 数据清洗完成，共 1200 行
# [14:32:05] 调用API分析...

看出错日志，一眼就知道挂在哪一步，不用从头猜。关键节点都要打日志：读数据、清洗、调API、出结果。

关键认知：不是写了 try/except 就够了

核心区别：新手以为 try/except 是「加上了就安全了」。老手知道：每种错误该怎么处理，才是真正要想的事。
错误类型糟糕的处理好的处理
文件不存在静默跳过提示用户检查路径，明确退出
API 超时直接放弃重试 3 次，仍失败则降级或报错
列名不匹配except 掉就行先 strip 清洗，打印实际列名排查
缺失值报错except 后返回空先 fillna 再算，结果有保障

问自己三个问题：这个错误会发生吗？发生了用户能看懂吗？发生后程序还能继续吗？想清楚这三件事，比堆 10 个 try/except 更有用。

完整示例：给分析流水线加错误处理

回顾第 21 课的流水线：读数据 → 清洗 → 调AI分析 → 输出结果。加上错误处理后，它从 demo 变成了可靠工具：

from datetime import datetime
import time, requests, pandas as pd

def log(msg):
    print(f"[{datetime.now():%H:%M:%S}] {msg}")

def call_api(payload, retries=3):
    for i in range(retries):
        try:
            r = requests.post(URL, json=payload, timeout=30)
            r.raise_for_status()
            return r.json()
        except Exception as e:
            log(f"API第{i+1}次失败: {e}")
            if i < retries - 1: time.sleep(3)
    return None

# ---- 主流程 ----
log("① 读取数据")
try:
    df = pd.read_csv('台区数据.csv')
except FileNotFoundError:
    log("❌ 文件不存在，请检查路径")
    raise

log("② 清洗数据")
df.columns = df.columns.str.strip()
df['用电量'] = df['用电量'].fillna(0)

log("③ 调用AI分析")
result = call_api({'data': df.head(20).to_dict()})
if result is None:
    log("⚠️ API不可用，跳过AI分析")
else:
    log(f"✅ 分析完成: {result['summary']}")

对比第 21 课的版本：同样的流程，但现在文件不存在会提示、API 失败会重试、列名有空格会清洗、每步都有日志。这就是从 demo 到工具的距离。

🤔 小测

你的分析脚本突然报错 KeyError: '用电量'，最可能的原因是什么？

  1. Python 版本太低
  2. CSV 文件里这列的名字不是「用电量」，可能是「电量」或有空格
  3. pandas 没装
  4. 电脑内存不够

💬 脚本报错不可怕，可怕的是不知道为什么报错。遇到报错先看错误类型和行号，90% 的问题能自己解决。
