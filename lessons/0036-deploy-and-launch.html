🚀 部署与上线

第 0036 课 · P5 实战篇 工程化课 · 预计 20 分钟

🎯 本课目标：把 34／35 课的 Agent 从「只在你电脑上活着」变成「别人拿得到、跑得起来、点得开看」。心法一句话：部署不是更高深的技术，是把三件小事补全——依赖说清、密钥分离、入口明确。

一、先破除神秘感：部署到底在做什么

现在你的 Agent 是什么状态？在你自己电脑上敲 python agent.py，它跑得好好的。但——

  • 你关机，它就没了（不像网页，你不会的时候它还开着）；
  • 你把文件夹发给别人，对方一运行就报一堆错；
  • 换台电脑、换个目录，你自己都跑不起来。

部署就是修掉上面这三件事：让程序在别人的机器上，或者一台别人能访问到的机器上跑起来。它考的从来不是算法，是交付习惯。

📌 关键认知：「在我电脑上跑」和「能交付」之间，差的不是技术难度，而是三件你脑子里有、但没写下来的事：装了哪些库（依赖）、key 从哪来（配置）、从哪个文件启动（入口）。写下来，就交付了。

二、诊断：为什么「发个文件夹」过去就跑不起来

坑对方看到什么正解
依赖没写 ModuleNotFoundError: No module named 'pandas'——对方根本不知道要装什么 列一份 requirements.txt，写清所有第三方库
密钥混在代码里 要么对方没 key 跑不起来；要么你的密钥跟着代码到处跑 代码只读环境变量；给一份 .env.example 模板，对方自己填值
绝对路径写死 FileNotFoundError: D:\学习\...——你电脑上的路径，别人机器上不存在 用相对路径，或 Path(__file__).parent 定位脚本所在目录
数据没跟着走（或真数据跟着走了） 示例数据缺失 → 跑不动；真实业务数据进了仓库 → 合规风险 示例数据提交进仓库；真实数据写进 .gitignore 绝不提交
⚠️ 接 35 课的安全闸①：密钥永远不写死在脚本里。这条在单人本地跑时是「好习惯」，一旦要交付就变成「必须」——因为你迟早会把代码给别人、或者推到 GitHub。

三、三级阶梯：按成本从低到高，别一步跳到最贵的

阶梯 0 · 可复现仓库（0 元，今天就能完成）

交付物＝一个 git 仓库，里面有几样固定成员：

README.md（怎么装、怎么配 key、怎么跑）
requirements.txt（依赖清单）
.env.example（配置模板，只有键名没有值）
.gitignore（挡住 .env 和真实数据）
data/sample.csv（示例数据）
main.py（入口）

别人 git clone → 配好 key → 一条命令跑起来。这就是「部署」的最小完整形态，多数场景足够用。

⭐ 对求职价值最高的一级：面试官最认「我 clone 下来、按你的 README 跑通了」——这比任何自我描述都硬。

阶梯 1 · 免费托管平台（0 元，要的是一个链接）

当你要的是「给个网址就能点开看」（43／44 课的作品、给人演示）时，用 Streamlit Community Cloud：GitHub 账号登录 → 选仓库／分支／入口文件 → Deploy，就是官方说的三步（streamlit.io/cloud）。之后你每次 git push，线上应用自动更新。

key 怎么办：不放代码，放平台自带的 Secrets 配置里，代码用 st.secrets 读——本质还是 35 课那条铁律，只是「环境变量」换了个存放位置。

⚠️ 一个必须自己实测的点：这类境外托管平台在国内网络下能否直接打开，各人网络环境不同。投递简历链接之前，先用手机流量和公司网络各开一次——打不开的链接比没有链接更伤。

阶梯 2 · 国内云（要花钱，解决「连数据库／给内网访问」）

真到要连公司数据库、或让客户在内网访问时，才上这一级：

  • 阿里云函数计算 FC「Web 函数」：支持自带 Flask 等 Web 框架，按实际资源用量计费，不访问不计费；新账号首次登录可领试用额度（官方文档）。
  • 腾讯云 Serverless HTTP（云函数 SCF）：同样按量付费，Python 支持 Flask／Django 这类 WSGI 框架。
  • 轻量应用服务器：最直白的一台小服务器，年付百元级起，装什么跑什么。

本课只认路，不实操——43-45 课真需要了再上。记住顺序：先用 0 元的跑通全流程，缺什么再补什么，别一上来就买服务器。

四、部署前检查清单（本课最该带走的东西）

部署失败，九成死在这六条。以后每次要「交出去」，照着过一遍（也存成了独立速查页）：

  • 依赖写全：pip freeze > requirements.txt，或手写只列用到的库。
  • key 不写死：代码里只有 os.environ.get("DEEPSEEK_API_KEY")；值放本地 .env（不提交）＋ 一份 .env.example（提交）。
  • 没有绝对路径：全用相对路径或 Path(__file__).parent。
  • 示例数据随仓库走：没有数据对方跑不动；真实业务数据一律进 .gitignore。
  • README 第一行就是启动命令：pip install -r requirements.txt → 配 key → python main.py。
  • 「假装自己是别人」跑一遍：换个目录（或换台电脑）clone 下来，严格照 README 走一遍——报的每一个错，都是你漏掉的检查项。

五、实操任务（30 分钟）

教练给你备了一份可交付模板：lessons/code/deploy_kit/（README、requirements、.env.example、.gitignore 都写好了，每个文件都有注释说明该填什么）。用它把 34／35 课那个 Agent 变成可交付仓库：

  1. 把 deploy_kit/ 复制到你的项目目录，把 agent35_eval_demo.py 一起放进去。
  2. 填 requirements.txt：把你真正 import 过的库列上（pandas、openai 之类）。
  3. 把脚本里所有 key 读取统一改成 os.environ.get(...)，本地建 .env 填上值，跑通一次。
  4. 照模板写 README：三段——装依赖、配 key、启动命令。
  5. 换个目录（比如 D:\tmp\test_clone）「假装自己是别人」，严格照 README 走一遍，把所有报错修掉。
🎯 本课核心结论：「部署」这个词听着像运维，实际是把你脑中隐含的三样东西写成文件——依赖、配置、入口。做完这一步，你的 Agent 就从「我的玩具」变成「一个东西」。37 课毕业项目要的「可展示 + 可部署」，地基就是本课这份仓库。

本课学了什么

  • ✅ 部署的本质：不是更难的技术，是交付习惯——依赖说清、密钥分离、入口明确
  • ✅ 四大交付坑：依赖没写／密钥混在代码里／绝对路径／数据没跟着走
  • ✅ 三级阶梯：0 元可复现仓库 → 免费托管平台（st.secrets 放 key）→ 国内云（按量付费／轻量服务器）
  • ✅ 六条检查清单：交给别人之前逐条过一遍，「假装自己是别人」跑一次

🤔 小测

你要把 34 课的 Agent 交给同事试用，同事电脑上没装任何东西。下面哪种做法最能让同事真的把它跑起来？

  1. 把整个项目文件夹压缩成 zip 发过去，让对方自己摸索运行方式
  2. 给一个 git 仓库，含 README、依赖清单、.env.example，对方配好 key 一条命令跑起来
  3. 把自己可用的 API key 一起写进代码里，对方拿到就能直接运行
  4. 录一段自己本地运行的完整屏幕录像发过去，让对方照着复现

小测答案：B。仓库 + README + 依赖清单 + .env.example，对方自配 key 后一条命令跑起来——这正是本课「可复现仓库」的定义：依赖、配置、入口三样都写清楚了，对方不需要你在场。
A 错：zip 里没有依赖清单、没有 key 说明、路径还是你机器上的绝对路径，对方拿到就是一堆报错——「发出去」不等于「交付」。
C 错：把你的 key 写进代码，等于把家门钥匙连同房子一起送人——密钥泄露、费用记在你账上。这正好违反 35 课安全闸①。
D 错：录像只能证明「你电脑上能跑」，不能证明「别人电脑上能跑」。同事照着复现，卡在环境那一步照样过不去，而你还不知道错在哪。
这题的教训：「能交付」的标准不是「我发过给他」，而是「他不需要我在场也能跑起来」。判断方法只有一个——换个干净目录，假装自己是别人，跑一遍。
