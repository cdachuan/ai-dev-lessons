关键发现：它们其实是「一个骨架 + 换零件」

回头看，这五个脚本长得几乎一样，都是同一套三步骨架：

# 所有工具的通用骨架
1. 读入   → 文件 / 文件夹 / 表格
2. 组装   → 拼成 AI 能读的文字 + 一段 system prompt
3. 调用   → 发给 API，拿回结果

换一句话说：你不是学了五个脚本，而是学会了一套模式。以后遇到任何新的重复劳动，套这个骨架、改 system prompt，就是一个新工具。

把工具箱组织起来

建议在电脑上建一个专门的文件夹，把工具都收进去：

我的AI工具箱/
├── daily_report.py       # 0011 日报
├── excel_extract.py      # 0012 Excel 分析
├── merge_sources.py      # 0013 多源合并
├── template_filler.py    # 0014 模板填充
├── config.py             # 统一放 API Key、base_url
└── README.md             # 记下每个工具怎么用
💡 一个小改进：把 API Key、base_url 抽到一个 config.py 里，所有脚本都 from config import client。以后换 Key 或换模型，只改一处，五个工具全跟着变。这就是「不要重复自己」（DRY）。

下一步：从「工具」到「组合」

真正的威力在组合。比如把三个工具串起来，配上定时器：

每周五 17:00（0015 定时）→ 扫描本周素材文件夹（0013 合并）→ 生成周报草稿 → 套进周报模板（0014 填充）→ 存档

整条流水线跑完，你周五下班前的周报就自动躺在那了。这，就是你亲手搭的自动化。

工具篇你学到了什么

  • ✅ openpyxl 读 Excel、pathlib 遍历文件夹
  • ✅ 用 def 封装函数、用占位符 + .format() 填模板
  • ✅ 「读 → 组装 → 调用」的通用骨架，一套模式解决一类问题
  • ✅ 用系统调度器让工具自动运行
  • ✅ 把散装脚本组织成一个可复用、可组合的工具箱
🎓 结业寄语：你从「什么是 AI 模型」一路走到「亲手搭一套自动化工具箱」。工具本身会过时，但你掌握的这套「识别重复劳动 → 拆成读/组装/调用 → 交给 AI + 定时器」的思维不会。这才是这门课真正想给你的东西。
