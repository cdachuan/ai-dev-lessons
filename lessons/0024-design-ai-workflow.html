🧩 设计 AI 工作流：从需求到方案

第 0024 课 · 总结篇·一 概念课

🎯 本课目标：学会拿到一个工作问题后，先判断该用什么 AI 方案，而不是上来就写代码。掌握三条路线的区别，学会用决策树选路线。

先想清楚，再动手

前面 23 课你学了很多工具：Python 脚本、pandas 数据分析、matplotlib 画图、Coze 工作流、智能体……但工作中真正的问题不是「会不会用工具」，而是「这个任务到底该用哪种工具」。

举个真实的场景：同事跑来找你——

"帮我做个 AI，能自动分析台区数据，还能回答问题。"

你脑子里该浮现的第一个问题不是「用什么模型」，而是「这个需求拆开来看，到底有几件事？每件事适合哪种方案？」

🔑 核心认知：先画流程，再写代码。就像写作文先列提纲——提纲列好了，正文自然顺。跳过提纲直接写，大概率写着写着就乱。

三条路线：脚本 → 工作流 → Agent

AI 解决工作问题，万变不离其宗，就三条路线：

路线特点适合什么任务你学过的例子
脚本 固定流程，跑一遍出结果 步骤固定、规则明确 pandas 算指标 + matplotlib 画图
工作流 多步骤编排，每步有明确职责 步骤多、每步逻辑不同、需要串联 Coze 工作流：意图识别 → 查数据 → 组织回答
Agent 自主决策，根据情况选择行动 需要灵活判断、路径不固定 Hermes 智能体：根据任务自动选工具

怎么理解三者的区别

用一个比喻来记：

  • 脚本 = 食谱 —— 按步骤做，每一步写死了，照做就行
  • 工作流 = 流水线 —— 分了工，每站干自己的事，上一站的输出是下一站的输入
  • Agent = 厨师 —— 给他食材和目标，他自己决定先切还是先炒，遇到问题自己调整

食谱最省心但最死板，厨师最灵活但最难控制，流水线居中。越灵活的方案，开发和维护成本越高——别为了「灵活」而灵活。

决策树：三个问题选路线

拿到一个任务，问自己三个问题，答案就出来了：

任务固定吗？
├─ 是 ──→ 步骤多吗？
│        ├─ 不多（1~3步）──→ 【脚本】
│        └─ 多（4步以上）──→ 【工作流】
└─ 否 ──→ 需要灵活判断吗？
          ├─ 不太需要，只是分支多 ──→ 【工作流】
          └─ 需要，路径不可预测 ──→ 【Agent】
💡 三问口诀：固定吗？步骤多吗？需要判断吗？——三问答完，路线自现。

三个真实场景：走一遍决策树

场景 A：每月生成台区用电分析报告

需求：每个月固定从系统导出台区用电数据，算出波动指标，判断哪些台区异常，画图，生成一段分析文字。

走决策树：

  • 任务固定吗？→ 是，每个月都一样
  • 步骤多吗？→ 不多，就是「算 → 判 → 画」三步
  • → 选脚本

架构图：

阶段输入处理输出
① 算月度用电 CSVpandas 算波动指标指标表
② 判指标表AI 判断哪些台区异常结论文字
③ 画指标表matplotlib 画柱状图波动图 PNG
④ 合结论 + 图拼成报告月度报告

流程写死，每月跑一次，稳定输出。没必要上工作流或 Agent——杀鸡不用牛刀。

场景 B：选手提问自动回答（大赛）

需求：大赛中选手在系统里提问，可能是查规则、查数据、查赛程，需要 AI 自动识别问题类型并给出准确回答。

走决策树：

  • 任务固定吗？→ 不完全固定，问题类型不同
  • 需要灵活判断吗？→ 不太需要，问题类型有限，可枚举
  • → 选工作流

架构图：

阶段输入处理输出
① 识别选手问题LLM 判断意图（规则/数据/赛程）意图标签
② 查询意图标签根据意图查对应知识库/数据库原始素材
③ 组织原始素材 + 原问题LLM 组织成自然语言回答回答文本

每一步职责清晰，上一步的输出喂给下一步。这就是你在 Coze 里搭过的东西。如果用脚本写，判断逻辑会越堆越乱；用 Agent 又太重——问题类型就那几种，不需要自主决策。

场景 C：分析哪些台区需要重点检查

需求：领导说"看看哪些台区该重点检查一下"。这个任务没有固定标准——要综合考虑用电波动、线损率、历史投诉、设备年限、最近天气……而且每个月权重可能都不一样。

走决策树：

  • 任务固定吗？→ 不固定，考虑因素多变
  • 需要灵活判断吗？→ 需要，路径不可预测
  • → 选 Agent

架构图：

阶段处理说明
输入自然语言指令 + 台区数据"帮我看看哪些台区要重点检查"
思考Agent 自主决定查什么可能查波动，也可能查投诉，取决于上下文
行动调用工具（算指标/查记录/画图）自己决定先做什么、再做什么
输出分析报告 + 建议清单综合判断后的结论

这种任务如果硬写成脚本，你得把所有可能的组合都列出来，维护噩梦。如果用工作流，分支太多，画到最后变成蜘蛛网。Agent 的价值就是「你自己看着办」——给它工具和目标，让它自己决定路径。

三条路线对比总结

维度脚本工作流Agent
灵活性低（固定流程）中（分支可控）高（自主决策）
开发成本低中高
维护成本低中高（行为不完全可控）
适合场景每月固定报告大赛问答系统综合分析判断
典型工具Python + pandasCoze 工作流Hermes / Coze Agent
⚠️ 常见误区：不是越灵活越好。能用脚本就别用工作流，能用工流就别上 Agent。过度设计 = 自己给自己挖坑。简单方案能解决问题，就是好方案。

先画流程，再写代码

这三个字说起来简单，但 80% 的人做不到。大多数人拿到需求的第一反应是「打开 Coze 拖一个节点」或者「让 AI 帮我写代码」。

正确的做法是：先拿出一张纸（或打开一个空白文档），用文字画出流程。

  1. 写输入：这个任务的数据/信息从哪来？
  2. 写处理：需要经过哪几步？每步做什么？
  3. 写输出：最终产出是什么？给谁看？
  4. 标路线：根据决策树，这条流程选脚本、工作流还是 Agent？
  5. 再动手：流程清楚了，再打开工具开始搭。
💡 像写作文先列提纲：你不会提笔就写一篇 3000 字的文章——先列提纲：开头写什么、中间几个论点、结尾怎么收。AI 方案设计同理：先画流程（输入 → 处理 → 输出），再写代码。提纲五分钟，省你五小时。

🤔 小测

你的同事说「帮我做一个能自动回复群里消息的 AI」，你应该先问什么？

  1. 用什么模型
  2. 消息类型有哪些？回复需要查数据吗？有固定模板吗？
  3. 用 Python 还是 Java
  4. 预算多少

💬 选路线不是技术问题，是思维问题。先想清楚要做什么，再决定怎么做。
