🤖 多工具 Agent：ReAct 循环的代码实现

第 0028 课 · P5 实战篇 实操课

🎯 本课目标：在 27 课的 1 工具 1 调用基础上，注册 3-4 个工具，用 while 循环实现 Thought → Action → Observation 多轮调用，让 Agent 自己决定「下一步该调哪个工具、调几次、什么时候停」。学完你就有了「能处理多步任务的 Agent」骨架。

从「一个工具」到「多工具」的真正变化

27 课的脚本只能处理「一步到位」的问题：用户问一个数据，AI 调一个工具，AI 回答。但真实工作里，你的问题往往需要多步：

  • 「T07 台区 8 月 22 号用了多少度电，比前一天多了几个百分点？」——要查两次，还要算百分比
  • 「帮我把这份数据按台区分组算总量，再画个图—— AI 要先读文件，再算，再画
  • 「T07 和 T12 哪个台区昨天的线损率更高？高多少？」——查两个台区、算两个指标、做对比

这种需要多次工具调用、调用顺序和次数都不固定的问题，27 课的代码搞不定。今天加一个 while 循环，把 Agent 从「调一次」升级到「一直调到 AI 自己喊停」。

📌 ReAct 是什么：ReAct = Reasoning（思考）+ Acting（行动）。AI 每一步都先「想」下一步该做什么（「我需要先查 T07 22 号的电量」），再「动」（调工具），看到结果（Observation）后再「想」下一步。这就是 Agent 的核心循环。

设计四个工具，覆盖一组真实问题

围绕「查台区电量、做对比、出报告」这个真实场景，我们注册四个工具：

工具名能做什么什么时候用
query_taigu_kwh查某台区某日电量用户问「多少度电」
query_line_loss_rate查某台区某日线损率（%）用户问「线损」
compare_taigus对比两个台区某指标的差值用户问「哪个高/低」
calculate_pct_change算两数增减百分比用户问「比……多了几个百分点」
💡 为什么是这四个：它们有依赖关系——「对比」要底层数据，「算百分比」要两个数。这就是真实任务的拆解：复杂问题=多个简单工具组合。28 课让你看见这个组合的过程。

第一步：四个工具函数 + 一份说明书

这四个函数和 27 课一样，是普通的 Python 函数——AI 帮你决定「调哪个、按什么顺序调」，但函数本身是你的代码在工作。

# tools_4.py —— 四个工具函数

# 模拟台区数据
MOCK = {
    "T07": {"kwh": {"2026-08-21": 1180.2, "2026-08-22": 1320.8},
            "loss": {"2026-08-21": 3.2,   "2026-08-22": 4.1}},
    "T12": {"kwh": {"2026-08-21": 1020.1, "2026-08-22": 995.7 },
            "loss": {"2026-08-21": 2.8,   "2026-08-22": 2.5}},
}

def query_taigu_kwh(taigu_id, date):
    """查某台区某日用电量（kWh）"""
    kwh = MOCK.get(taigu_id, {}).get("kwh", {}).get(date)
    if kwh is None: return {"error": f"无数据: {taigu_id}/{date}"}
    return {"taigu_id": taigu_id, "date": date, "kwh": kwh}

def query_line_loss_rate(taigu_id, date):
    """查某台区某日线损率（%）"""
    rate = MOCK.get(taigu_id, {}).get("loss", {}).get(date)
    if rate is None: return {"error": f"无数据: {taigu_id}/{date}"}
    return {"taigu_id": taigu_id, "date": date, "loss_rate_pct": rate}

def compare_taigus(taigu_a, taigu_b, metric, date):
    """对比两台区某指标在某日的差值（a - b）"""
    src = MOCK.get(taigu_a, {}).get(metric, {}).get(date)
    dst = MOCK.get(taigu_b, {}).get(metric, {}).get(date)
    if src is None or dst is None:
        return {"error": "数据缺失"}
    return {"a": taigu_a, "b": taigu_b, "metric": metric,
            "date": date, "diff": round(src - dst, 2)}

def calculate_pct_change(old_value, new_value):
    """算 (new - old) / old * 100%，返回百分比"""
    if old_value == 0: return {"error": "基数为 0，无法算百分比"}
    pct = round((new_value - old_value) / old_value * 100, 2)
    return {"old": old_value, "new": new_value, "pct_change": pct}

接下来写一份说明书（tools schema），把四个函数告诉 AI。每个工具的 description 决定 AI 会不会选它：

from tools_4 import query_taigu_kwh, query_line_loss_rate, compare_taigus, calculate_pct_change

TOOL_REGISTRY = {
    "query_taigu_kwh": query_taigu_kwh,
    "query_line_loss_rate": query_line_loss_rate,
    "compare_taigus": compare_taigus,
    "calculate_pct_change": calculate_pct_change,
}

tools = [
    {"type": "function", "function": {
        "name": "query_taigu_kwh",
        "description": "查询指定台区在某一天的用电量（kWh）。当用户问某台区某天的用电量时使用。",
        "parameters": {"type": "object", "properties": {
            "taigu_id": {"type": "string", "description": "台区编号，如 T07"},
            "date":    {"type": "string", "description": "日期 YYYY-MM-DD"}},
        "required": ["taigu_id", "date"]}}},
    {"type": "function", "function": {
        "name": "query_line_loss_rate",
        "description": "查询指定台区在某一天的线损率（百分比）。当用户问线损/损耗时使用。",
        "parameters": {"type": "object", "properties": {
            "taigu_id": {"type": "string", "description": "台区编号"},
            "date":    {"type": "string", "description": "日期 YYYY-MM-DD"}},
        "required": ["taigu_id", "date"]}}},
    {"type": "function", "function": {
        "name": "compare_taigus",
        "description": "对比两个台区在某日的某指标差值（a - b）。当用户问两个台区谁高/低/差多少时使用。",
        "parameters": {"type": "object", "properties": {
            "taigu_a":  {"type": "string",  "description": "台区 A 编号"},
            "taigu_b":  {"type": "string",  "description": "台区 B 编号"},
            "metric":  {"type": "string",  "description": "指标: 'kwh' 或 'loss'"},
            "date":    {"type": "string",  "description": "日期 YYYY-MM-DD"}},
        "required": ["taigu_a", "taigu_b", "metric", "date"]}}},
    {"type": "function", "function": {
        "name": "calculate_pct_change",
        "description": "计算两个数值之间的增减百分比 (new-old)/old*100。当用户问"比前一天多了几个百分点"时使用。",
        "parameters": {"type": "object", "properties": {
            "old_value": {"type": "number", "description": "旧值（基期）"},
            "new_value": {"type": "number", "description": "新值（当期）"}},
        "required": ["old_value", "new_value"]}}},
]
💡 关键设计：TOOL_REGISTRY 字典——把工具名映射到 Python 函数。这样 AI 让你「调 query_taigu_kwh」时，你的代码用 TOOL_REGISTRY[name](**args) 就能找到并执行它。新增工具时只改两处：写函数 + 加进 registry。

第二步：ReAct 循环（核心 30 行）

27 课只有「1 次调用」，28 课加一个 while 循环，让 AI 一直调到它自己回答为止：

Thought（AI 想下一步）
↓
Action（AI 说调哪个工具）
↓
Observation（你的代码执行，结果喂回）
↓
再次 Thought（AI 看到结果再想）
↓
... 直到 AI 不再调工具，自己组织答案 ...

完整脚本：

# agent_react.py
import json
from openai import OpenAI
from tools_4 import TOOL_REGISTRY

client = OpenAI(api_key="sk-你的密钥", base_url="https://api.deepseek.com")

def run_agent(user_query, max_steps=6):
    messages = [{"role": "user", "content": user_query}]

    for step in range(max_steps):
        # ① Thought + Action：让 AI 想下一步、决定调不调工具
        resp = client.chat.completions.create(
            model="deepseek-chat",
            messages=messages,
            tools=tools
        )
        msg = resp.choices[0].message

        # ② AI 不调工具 → 给最终答案，结束
        if not msg.tool_calls:
            return msg.content

        # ③ AI 调工具 → 全部执行，把结果喂回
        messages.append(msg)  # 必须先 append AI 的消息
        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            print(f"  [step {step+1}] → {call.function.name}({args})")

            # ← 你的代码实际执行工具
            try:
                result = TOOL_REGISTRY[call.function.name](**args)
            except Exception as e:
                result = {"error": f"执行失败: {e}"}

            # ④ Observation：把结果塞回对话
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": json.dumps(result, ensure_ascii=False)
            })

    return "（达到最大步数，Agent 还没给出答案）"

if __name__ == "__main__":
    print(run_agent("T07 台区 8 月 22 号用了多少度电，比前一天多了几个百分点？"))

这段代码核心就 30 行，加了 while（for step in range(max_steps)）和多工具遍历。和 27 课比，只有循环和 TOOL_REGISTRY 是新东西，其它都是 27 课已有的逻辑。

第三步：跑起来看 AI 怎么「自己调度」

跑这个问题：「T07 台区 8 月 22 号用了多少度电，比前一天多了几个百分点？」

$ python agent_react.py
  [step 1] → query_taigu_kwh({'taigu_id': 'T07', 'date': '2026-08-22'})
  [step 2] → query_taigu_kwh({'taigu_id': 'T07', 'date': '2026-08-21'})
  [step 3] → calculate_pct_change({'old_value': 1180.2, 'new_value': 1320.8})
T07 台区 2026-08-22 用电 1320.8 kWh，比前一天 1180.2 kWh 多了 11.9%。

看到没？AI 自己决定了：

  1. 先查 22 号电量（step 1）
  2. 看到结果，再查 21 号电量（step 2）
  3. 看到两个数，再调 calculate_pct_change（step 3）
  4. 看到百分比，自己组织答案，不再调工具，循环结束
💡 ReAct 的力量：你完全没写 if-else决定「该查哪天、该不该算百分比」。AI 看完每个工具的结果，自己推理下一步。这就是为什么叫「智能体」——它有自主决策能力，不是死板脚本。

第四步：故意刁难，看 AI 怎么应对

试试这几个不同问题，看 AI 怎么调度（拷到 __main__ 里跑）：

  • 「T07 和 T12 昨天线损率哪个高？高多少？」——AI 应该一次调 compare_taigus，因为这个工具直接返回差值，AI 不需要先查两个数再算。
  • 「今天北京天气怎么样？」——AI 看到没天气工具，应该直接文本回答「我没有这个工具」，不调用任何东西，step 1 就结束。
  • 「T07 8 月 22 号的电量，和 T12 比，谁多？算一下两个台区的差值百分比」——AI 可能先 query_taigu_kwh 两次，再 compare_taigus 拿差值，最后 calculate_pct_change 算百分比，3-4 步走完。

这就是 ReAct 的动态性——同样四问，调几次、调哪些工具，AI 自己定。

⚠️ 兜底保护：max_steps=6——限制最多 6 轮工具调用。万一 AI 死循环（反复调同一工具），到 6 步强制退出。真实工程里必加，否则一次任务烧光你的 API 额度。35 课会专门讲这个。

和 27 课的关键区别

维度27 课（1 工具）28 课（多工具 ReAct）
工具数1 个3-4 个
调用次数0 或 1 次0 到 N 次（N 由 AI 决定）
循环无（一次 create 完事）有（for step in range()）
代码行数~60 行~90 行（多 30 行）
能处理的问题一步到位多步、需组合
兜底不需要max_steps 必加

本课学了什么

  • ✅ 注册 4 个工具：查电量、查线损、对比、算百分比
  • ✅ 用 TOOL_REGISTRY 字典把工具名映射到 Python 函数
  • ✅ 用 for step in range(max_steps) 实现 ReAct 循环
  • ✅ 让 AI 自主决定：调几次、调哪些、什么时候停
  • ✅ 加 max_steps 兜底，防止死循环
  • ✅ try/except 包装工具执行，错误也能塞回给 AI 继续推理
