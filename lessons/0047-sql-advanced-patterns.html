第 0047 课 · 选修线一 SQL与查询工程 · 预计 25 分钟

🎯 本课目标：掌握四个面试笔试出现率最高的 SQL 业务模式。它们难不在语法，在「把业务语言翻译成 SQL 结构」的套路。每个模式都用你的 54 万行数据真跑过，数字可直接对照。

模式一：留存分析（自 JOIN / 队列）

业务问题：12 月第一次来的客户，1 月、2 月还在买的有多少？——先给每个客户打上「首购月份」标签（队列 cohort），再看后续每个月还有谁活跃。

WITH first_purchase AS (          -- 每个客户的首购月 = 队列标签
  SELECT CustomerID,
         date_trunc('month', MIN(InvoiceDate)) AS cohort
  FROM df WHERE CustomerID IS NOT NULL AND UnitPrice > 0
  GROUP BY 1
),
activity AS (                     -- 每个客户的每次活跃月
  SELECT DISTINCT f.CustomerID, f.cohort,
         date_trunc('month', d.InvoiceDate) AS act_m
  FROM first_purchase f JOIN df d USING (CustomerID)
  WHERE d.CustomerID IS NOT NULL AND d.UnitPrice > 0
)
SELECT cohort,
       COUNT(DISTINCT CustomerID) AS cohort_size,
       COUNT(DISTINCT CASE WHEN act_m = cohort + INTERVAL 1 MONTH
                           THEN CustomerID END) AS m1,   -- 次月还活跃
       COUNT(DISTINCT CASE WHEN act_m = cohort + INTERVAL 2 MONTH
                           THEN CustomerID END) AS m2    -- 隔月还活跃
FROM activity GROUP BY cohort ORDER BY cohort LIMIT 4

模式二：漏斗（每一步都数一遍）

业务问题：订单里有几张是多品类单？客户里有多少跨月复购？——漏斗本质是每一步独立计数，再算相邻转化率：

WITH orders AS (
  SELECT InvoiceNo, COUNT(DISTINCT StockCode) AS skus
  FROM df
  WHERE CustomerID IS NOT NULL AND UnitPrice > 0 AND Quantity > 0
  GROUP BY 1
)
SELECT COUNT(*) AS total_orders,
       COUNT(CASE WHEN skus > 1 THEN 1 END) AS multi_item
FROM orders
-- 18532 单 → 17125 张多品单（92.4%）
-- 第三步（跨月复购客户）单独算：2800 人
⚠️ 漏斗三大坑：① 各步的统计对象不同（单/人/次）直接相除会算错——先统一「算谁的转化」；② 步骤之间有时间顺序的（浏览→加购→支付），必须先按时间排序再判「后一步晚于前一步」；③ 分子分母口径不同源（一个用埋点一个用订单）是假漏斗。

模式三：TopN per Group（窗口函数经典）

业务问题：每个国家卖得最好的 2 个商品。——GROUP BY 做不到（它只能给国家总排名），要用 ROW_NUMBER：

SELECT * FROM (
  SELECT Country, Description,
         ROUND(SUM(Quantity * UnitPrice), 0) AS gmv,
         ROW_NUMBER() OVER (PARTITION BY Country
                            ORDER BY SUM(Quantity * UnitPrice) DESC) AS rn
  FROM df
  WHERE CustomerID IS NOT NULL AND UnitPrice > 0
  GROUP BY Country, Description
) WHERE rn <= 2 AND Country IN ('Netherlands', 'Germany')
ORDER BY Country, rn
-- Netherlands  RABBIT NIGHT LIGHT               9568   rn=1
-- Netherlands  ROUND SNACK BOXES SET OF4 ...    7991   rn=2
-- Germany      POSTAGE                         20821   rn=1
-- Germany      REGENCY CAKESTAND 3 TIER         8257   rn=2

三个排名函数的区别（笔试常考）：销售额并列 100 的两个商品，下一个是 90：

函数并列后下一名
ROW_NUMBER强制分先后 1,23
RANK并列 1,13（跳号）
DENSE_RANK并列 1,12（不跳号）
📌 数据又坑你了：德国 Top1 是 POSTAGE（邮费）——40 课讲过的非商品项。TopN 分析前先定义「商品」边界，不然榜单被邮费占领。

模式四：同环比（LAG / LEAD）

业务问题：本月 GMV 比上月变化多少？比去年同期呢？

WITH m AS (
  SELECT date_trunc('month', InvoiceDate) AS mo,
         SUM(Quantity * UnitPrice) AS rev
  FROM df WHERE CustomerID IS NOT NULL AND UnitPrice > 0
  GROUP BY 1
)
SELECT mo, ROUND(rev, 0) AS rev,
       ROUND(rev / LAG(rev)     OVER (ORDER BY mo) - 1, 3) AS mom,   -- 环比(上月)
       ROUND(rev / LAG(rev, 12) OVER (ORDER BY mo) - 1, 3) AS yoy    -- 同比(去年同月)
FROM m
-- 2011-01: mom=-0.143   2011-03: mom=+0.329
-- LAG(x, 12) = 往上数 12 行，这就是同比；数据只有13个月，yoy 多数为 NULL，正常

动手任务（25 分钟）

  1. 跑通留存查询，对上课文表格里 2010-12 队列的 948/362/317。
  2. 把留存查询加一列 m3（隔两月），观察 2010-12 队列的留存曲线。
  3. 用 DENSE_RANK 重跑 TopN，构造一个并列场景，对比三种排名函数的差异。
  4. 算每周的订单量环比，找出 2011 年涨幅最大的一周（date_trunc('week', ...)）。
🎯 本课核心结论：四个模式 = 四种「行集变形」：留存是自 JOIN 打队列标签，漏斗是分步独立计数，TopN 是PARTITION 内排名，同环比是LAG 错位引用。面试看到业务题，先判断它是哪个变形，再落 SQL。

本课学了什么

  • ✅ 留存：首购队列 + 自 JOIN，按队列分开看不要算总账
  • ✅ 漏斗：每步独立计数，统一「算谁」的口径，警惕假漏斗
  • ✅ TopN per Group：ROW_NUMBER/RANK/DENSE_RANK 并列行为不同
  • ✅ 同环比：LAG 一行搞定，LAG(x,12) 即同比

🤔 小测

「每个品类销量第 2 的商品」该用什么？

  1. GROUP BY category ORDER BY sales LIMIT 2
  2. ROW_NUMBER() OVER (PARTITION BY category ORDER BY sales DESC) = 2
  3. DENSE_RANK() OVER (PARTITION BY category ORDER BY sales DESC) = 2
  4. SELECT MAX(sales) FROM ... GROUP BY category

（答案见底部）

← 上一课：SQL 实战 下一课：Text-to-SQL Agent → 📖 术语表

小测答案：B。「每个品类第 2 名」= PARTITION 内按销量降序的第 2 行，ROW_NUMBER 给并列也强制编 1,2,3，「第 2 名」唯一确定。
A 错：LIMIT 是全局前 2，不是「每个品类各取第 2」，而且 LIMIT 2 取的是第 1、2 名不是第 2 名。
C 错：DENSE_RANK 遇并列会出现两个第 1、没有第 2 或两个第 2——「第 N 名」语义被并列破坏，除非业务明确要并列语义。
D 错：MAX 只给最高分，拿不到「第 2 名是谁」。窗口函数 = 「组内排名/错位」类问题的唯一正解。
