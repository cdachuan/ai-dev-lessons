🗣️ pandasai：用大白话问数据

第 0032 课 · P5 实战篇 体验课

🎯 本课目标：体验「自然语言 → 分析结果」的一键链路，同时看清它的原理与边界。核心心法一句话：pandasai 负责「翻译」，你负责「把关」——它吐出的每个数，都要过得了你 31 课练出来的那双 pandas 眼睛。

它不是魔法：先看懂原理

名字很像「pandas 的 AI 版」，但 pandasai 不是一个新数据分析库，而是给 pandas 加了一个翻译层：大模型把你的中文问题翻译成 pandas 代码（或 SQL），在你本机执行这段代码，再把结果——数字、表格或图表——返回给你。

你的问题（大白话）
↓ ① 大模型翻译
pandas / SQL 代码
↓ ② 本机执行
数字 · 表格 · 图表

官方文档的原话是：pandasai 把自然语言转换成 Python 代码和 SQL 查询，再执行代码和数据交互，返回结果。所以它的体验像「聊天」，本质还是「写代码跑数」——只是写代码的人换成了大模型。

📌 关键认知：代码是「生成」的，不是「保证正确」的。大模型翻译可能翻错、可能用错列名、可能漏掉业务条件。这决定了下面所有用法——永远把它的输出当「待核验的草稿」，而不是「答案」。

装一个，跑一句（体验）

官方文档当前推荐版本（v3）要求 Python 3.8–3.11——你本机 3.11 正好在范围内。装两个包：主体 + 大模型接入扩展。

# 终端里装（需要联网）
pip install pandasai
pip install pandasai-litellm

然后跑一句最简体验：

import pandasai as pai
from pandasai_litellm.litellm import LiteLLM

# ① 配大模型：key 从环境变量读，别写死在代码里
llm = LiteLLM(model="gpt-4.1-mini", api_key=YOUR_API_KEY)
pai.config.set({"llm": llm})

# ② 读数据——还是熟悉的 pandas 家族，orders.csv 是 31 课那张模拟电商订单表
df = pai.read_csv("orders.csv")

# ③ 用大白话提问
resp = df.chat("按类目统计销售额，哪个类目最高？")
print(resp)

根据你问的问题，返回可能是文本、数字、表格或图表——「哪个类目最高」给数字，「画个每月销售额趋势图」给图，「把退货的订单列出来」给表格。

⚠️ 两句提醒：① 官方示例用 OpenAI，LiteLLM 是统一接口、可切换多种大模型（想用自己的模型时，以 pandas-ai 文档的 LLM 章节为准，别照抄网上旧写法——老教程里常见的 SmartDataframe 是 v2 的写法，新版入口是 pai.read_csv() + .chat()）。② 你的问题会被发送给外部大模型——涉及公司真实经营数据的问题，先想清楚数据能不能出内网，按你自己的数据边界规矩来。练习就用模拟的 orders.csv，效果一样。

为什么 31 课不能省：你才是把关人

如果 pandas 不熟，pandasai 的体验会「爽 5 分钟、坑一整天」——它给你一个数字，你不知道对不对、也不知道怎么反驳它。会 pandas 的人用法完全不同：

pandasai 可能犯的错例子
不懂口径把「已退款」的订单也算进销售额——31 课的三问（算谁/怎么算/要不要排除）它不会主动替你问
列名 / 字段幻觉把 amount 当成客户数来 count，或编一个不存在的列名
生成的代码本身有 bug条件写反、groupby 键选错，跑完不报错但结果错

把关清单——拿到它的任何结果，走三步：

  1. 要代码：让它把「怎么算的」展示出来（pandasai 能看到生成过程），或直接要求返回所用代码。
  2. 对口径：套 31 课的三问——算谁？怎么算？要不要排除？退款算了吗？客户数去重了吗？
  3. 复算：关键数字自己用 pandas 手写一遍，两边对上了才敢用。
# 关键数字自己复算一遍——10 秒钟的事，保住汇报的命
import pandas as pd
df = pd.read_csv("orders.csv")
valid = df[df["status"] == "已完成"]
print(valid.groupby("category")["amount"].sum())

什么时候用它（判断框架）

✅ 适合：

  • 探索性快问快答——「先随便看看数据里有什么」，像跟数据聊天
  • 给不懂代码的同事自助查数（pandasai 正是往这个方向做的）
  • 快速画个趋势图，看个大概方向

❌ 不适合：

  • 正式汇报口径——需要可解释、可复现，每一步都要经得起问
  • 涉及敏感 / 真实业务数据外传红线
  • 你还没法判断它答案对不对的场景（回到 31 课补 pandas）
🎯 和 34 课的伏笔：pandasai 本质上就是一个「会写 pandas 代码的 Agent 雏形」——大模型负责想（翻译成代码），工具负责算（执行）。34 课我们要亲手搭 Agent + 数据分析，思路一模一样：「想」和「算」分离，你在中间当验收官。这课先借 pandasai 把「翻译层」的感觉找好。

本课学了什么

  • ✅ 原理：pandasai = 大模型把中文翻译成 pandas/SQL → 本机执行 → 返回数字/表/图
  • ✅ 体验路径：pip 装两个包 → 配 LLM（key 走环境变量）→ pai.read_csv() + .chat()
  • ✅ 边界：代码是「生成」的不是「保证正确」的；口径、列名、代码 bug 三类坑
  • ✅ 把关清单：要代码 → 对口径 → 自己复算；正式汇报和敏感数据不靠它

  1. 让它再画一张图表，更直观
  2. 核验它生成的代码和口径
  3. 换一个更大的模型重新问

小测答案：B。核验代码和口径是唯一正解——这课的整条主线就是「翻译层不可信，你得把关」：pandasai 可能把退款订单也算进销售额（口径错），可能用错列（字段幻觉），可能生成有 bug 的代码，而这三类错误都不会报错，只会安静地给你一个错的数字。A 错：图画得再漂亮，源头数字是错的只会错得更隐蔽。C 错：换更大的模型是提升「翻译」的命中率，不是核验手段——同样的问题换个人翻译，你依然要自己验算。D 错：无关项。这题的教训：「AI 给的数」和「能写进汇报的数」之间，隔着你的 pandas 眼睛——先要代码、对口径、自己复算一遍，三关过了才轮得到汇报。
