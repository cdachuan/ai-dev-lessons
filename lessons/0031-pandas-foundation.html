🎯 本课目标：把 pandas 的四件套（读数据、筛选、分组、合并）练到「条件反射」，再补上透视表、日期处理、清洗三板斧。核心心法一句话：「Pandas 会写 ≠ 能回答业务问题」——先有业务问题，再选 pandas 操作，指标口径先于代码。

为什么先夯实 pandas？

接下来 34 课要做 Agent + 数据分析：Agent 负责「想」，pandas 负责「算」。如果 pandas 不熟，你会出现一个尴尬场面——Agent 把代码写出来了，你看不懂、也判断不了它对不对。Agent 分析数据的前提，是你自己得能读懂数据。

📌 新术语「指标口径」：同一个问题，不同算法会算出不同数字。「口径」就是「这个数到底怎么算的」的约定。比如「销售额」——是订单金额，还是去掉退款后的实付金额？口径不定，数字就没有意义。这是数据分析里最值钱的一个词。

四件套回顾：业务问题 → pandas 操作

每个操作都配一个真实业务问题，建立「问题 → 代码」的映射。我们的实战素材是一份电商订单表 orders.csv（后面 39-40 课的电商项目也会用同款数据）：

order_idcustomer_iddatecategoryamountstatus
1001C012026-08-01数码2999已完成
1002C022026-08-02服饰199已完成
1003C012026-08-03数码1599已退款
1004C032026-08-04食品89已完成
1005C022026-08-05服饰399已完成

① 读数据

import pandas as pd

df = pd.read_csv("orders.csv")          # 读 CSV
df = pd.read_excel("orders.xlsx")     # 读 Excel（需 openpyxl）
df.head()                          # 先看前 5 行，永远第一步
df.info()                          # 看每列类型 + 有没有缺失值

② 布尔筛选 —— 「找出符合条件的行」

# 业务问题：数码类目有哪些订单？
df[df["category"] == "数码"]

# 业务问题：金额超过 500 的订单
df[df["amount"] > 500]

# 多个条件用 &（且）和 |（或），每个条件都要加括号
df[(df["category"] == "数码") & (df["amount"] > 1000)]

③ groupby 分组聚合 —— 「按 XX 算 YY」

# 业务问题：每个类目的总销售额是多少？
df.groupby("category")["amount"].sum()

# 业务问题：每个客户下了几单？
df.groupby("customer_id")["order_id"].count()

口诀：「groupby(按谁分) + [对哪列] + 怎么算(sum/count/mean/max/min)」。

④ merge 合并 —— 「把两张表拼起来」

# 业务问题：订单表 + 客户表，查出每个订单的客户姓名
customers = pd.read_csv("customers.csv")   # customer_id, name, city
merged = pd.merge(df, customers, on="customer_id", how="left")
# how="left"：以左边（订单）为主，右边没有的填 NaN

进阶三件套（这课新学）

透视表 pivot_table —— 「二维交叉汇总」

# 业务问题：每个类目 × 每个月的销售额，一张表看全
df["month"] = pd.to_datetime(df["date"]).dt.month
pd.pivot_table(df, values="amount", index="category",
               columns="month", aggfunc="sum")

# 行 = 类目，列 = 月份，值 = 销售额。groupby 的二维版

日期处理 to_datetime —— 「把文本变成可计算的时间」

df["date"] = pd.to_datetime(df["date"])   # 字符串 → 时间类型
df["month"] = df["date"].dt.month       # 取月份
df["weekday"] = df["date"].dt.dayofweek  # 取星期几（0=周一）

清洗三板斧 —— 「脏数据怎么处理」

# 1. 缺失值：先看有多少，再决定删还是填
df.isna().sum()                          # 每列缺几个
df = df.dropna(subset=["amount"])     # 关键列缺了就删行
df["amount"] = df["amount"].fillna(0)  # 或填默认值

# 2. 重复值
df = df.drop_duplicates(subset=["order_id"])

# 3. 异常值：先描述统计，肉眼看异常
df["amount"].describe()   # min/max/mean，负数或离谱大数一眼可见
⚠️ 清洗铁律：删之前先想清楚。缺失值直接 dropna 最省事，但可能删掉有意义的行（比如「退款订单缺金额」恰恰是业务信号）。先 isna().sum() 看清楚规模，再决定策略——清洗动作永远要有理由，写进注释。

核心心法：指标口径先于代码

同样是 groupby("category")["amount"].sum()，不同人算出来可能差很多，因为口径没对齐。拿到业务问题的第一件事不是写代码，而是问三个问题：

  1. 算谁？——所有订单，还是只要「已完成」的？（status == "已完成" 先筛一遍）
  2. 怎么算？——求和、计数、去重计数、平均？「客户数」要 nunique()（去重），「订单数」用 count()（不去重）。
  3. 要不要排除异常？——退款、测试单、金额为 0 的单子算不算？
# 反面教材：直接算，口径没想
total = df["amount"].sum()   # 把退款也算进去了

# 正确姿势：先定口径，再写代码
# 口径：已完成订单的实付金额总和
valid = df[df["status"] == "已完成"]
total = valid["amount"].sum()   # 2999+199+89+399 = 3686
🎯 本课核心结论：pandas 的语法你已经会了，这课把它挂到业务问题上：读数据 → head()/info() 先摸底 → 定指标口径 → 筛选/分组/合并。以后 34 课 Agent 输出分析结果，你第一句要问的就是——「这个数的口径是什么？」

本课学了什么

  • ✅ 四件套挂业务问题：读（read_csv）、筛（布尔）、分（groupby）、拼（merge）
  • ✅ 进阶三件套：透视表 pivot_table、日期 to_datetime、清洗三板斧（缺失/重复/异常）
  • ✅ 指标口径：算谁 / 怎么算 / 要不要排除——先定口径再写代码
  • ✅ 「Pandas 会写 ≠ 能回答业务问题」：操作是手段，业务答案是目的

  1. len(df)
  2. df["customer_id"].nunique()
  3. df["customer_id"].count()
  4. df.groupby("customer_id").sum()

小测答案：B。nunique() = 去重计数。客户数必须去重——C01 下了 3 单也只算 1 个客户，正确答案是 7（C01、C02 加 5 个单客户）。A 错：len(df) 是订单行数 10，是「订单数」不是「客户数」。C 错：count() 数的是 customer_id 字段的出现次数（含重复），等于 10，同样不是客户数。D 错：groupby().sum() 是对金额求和，不是数客户。这题的教训：「数客户」和「数订单」是两个完全不同的问题，用错一个函数，汇报给领导的数字就错了。以后拿到任何「数 XX」的问题，先问一句：要不要去重？
