📄 动手写一个能读文件并总结的脚本

第 0008 课 · 2026-07-03 · 实践课

前几课学了概念（Token、Agent、Tool Calling），今天我们把它们串起来做一个真实能用的脚本。

🎯 增量胜利：学完这课，你就能写一个脚本：把任意文件丢给它 → AI 自动读并给出总结。马上能用在日常工作里。

问题场景

你是项目助理，每周要处理一堆报告、会议纪要、文章。以前的做法是：

  1. 手动打开文件，复制内容
  2. 粘到赫默对话框里
  3. 写"请总结一下"
  4. 等回复，再复制出来
  5. 重复 10 次（每个文件来一遍）

今天的脚本就是把这个流程自动化——人只需要执行一行命令，剩下的交给代码。

三步走

这个脚本只做三件事，每件事你都已经学过：

1 读文件 —— Python 的基本文件操作。把文件内容读到变量里。
2 调 API —— 用第 3 课学过的 client.chat.completions.create() 把内容发给 DeepSeek。
3 打印结果 —— 取出 response.choices[0].message.content，打印到屏幕上。

完整脚本

创建一个文件 summarize.py，复制以下代码：

from openai import OpenAI

# 1. 连接 API
client = OpenAI(
    api_key="sk-你的密钥",       # ← 改成你的 DeepSeek API Key
    base_url="https://api.deepseek.com"
)

# 2. 读文件
file_path = "report.txt"               # ← 改成你要总结的文件路径
with open(file_path, "r", encoding="utf-8") as f:
    content = f.read()

# 3. 构造 prompt（把文件内容嵌入到指令里）
prompt = f"""请用简洁的中文总结以下内容，100 字以内：

{content}
"""

# 4. 调 API
response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[
        {"role": "user", "content": prompt}
    ]
)

# 5. 输出结果
print("\n=== 总结 ===\n")
print(response.choices[0].message.content)

逐行解释

代码什么意思
from openai import OpenAI 引入第 3 课装的「openai」库，这是和 DeepSeek 对话的桥梁
open(file_path, "r", encoding="utf-8") open() 是 Python 内置的文件打开函数。"r" 表示只读模式。encoding="utf-8" 保证中文不乱码
content = f.read() 把文件的全部文本读进 content 这个变量里
f"请总结……{content}" f-string（格式化字符串）—— {content} 会被替换成文件的实际内容。这样 prompt = "请总结 xxx"
client.chat.completions.create(...) 跟第 3 课一模一样的 API 调用，区别是 prompt 里包含了文件内容
print(response.choices[0].message.content) 从 API 回复中取出 AI 生成的总结文字，打印到终端

运行试试

  1. 在当前目录下创建一个测试文件 report.txt，随便写几段话（比如你最近的一个任务说明）
  2. 把 api_key 改成你的 DeepSeek API Key
  3. 在终端中运行：
$ python summarize.py

=== 总结 ===
该报告主要讨论了第三季度的项目进度，核心问题是...
⚡ 注意：如果文件太大（比如几千字），可能会超出模型的上下文窗口（Token 过多）。关于如何分块处理长文档，是第 0009 课（RAG）的内容。今天先处理几百字的短文即可。

升级玩法

脚本写出来后，改几行就能做不同的事：

改哪里效果
把 prompt 里的"总结"改成"翻译成英文" 变成英译脚本
在 prompt 前面加 {"role": "system", "content": "你是一个专业的合同审查律师"} 变成合同审查助手
把 file_path 改成从命令行参数读入 变成通用工具：python summarize.py 任何文件
用 for file in files: 循环处理多个文件 批量处理一整批报告

🤔 小测

下面哪一项是 prompt = f"请总结：{content}" 中 f 的作用？

  1. 表示"文件"（file）的缩写
  2. 表示"格式化字符串"——把 {content} 替换为变量的实际值
  3. 表示"快速"（fast）——让代码运行更快
  4. 没有作用，可以去掉
