一、为什么要封装成「工具」而不是散写脚本？

37 课你的 capstone_kit 已经有了 4 个工具函数（profile、group_sum、count_distinct、group_count），38 课我们讨论了 Agent 工作流设计。现在到了电商场景，数据量更大、指标更多——如果还是每次分析都从头写一遍 pd.read_csv()、清洗、分组，你会陷入「重复造轮子」的泥潭。

封装成工具的核心好处：

散写脚本封装工具
每次分析都重复读数据、清洗读一次，复用多次
口径写在代码深处，容易遗忘参数显式传入，调用时可见
出错时不知道哪一步炸了结构化错误反馈，精确定位
Agent 不知道怎么调函数签名 + docstring = Agent 的说明书
📌 关键认知：工具的「说明书」不是给人看的——是给 Agent（大模型）看的。模型通过函数名、参数名、docstring 来决定「这个问题该调哪个工具、传什么参数」。所以好的工具 = 好的 API 设计。

二、工具设计四要素

每个工具函数必须包含四样东西，缺一不可：

① 工具描述（docstring）

告诉 Agent「这个工具干什么、什么时候该用」。不是给人看的注释，是 Agent 的决策依据。

# 差的描述：人能懂，Agent 不知道什么时候该调
def calc_gmv():
    """计算GMV"""

# 好的描述：Agent 知道用途、参数含义、调用时机
def calc_gmv(df, filter_status=None, group_by=None):
    """计算 GMV（总成交金额）。
    
    用途：回答"总销售额是多少"、"某个品类/渠道卖了多少钱"这类问题。
    口径：默认包含所有状态；传 filter_status="已完成" 只算成交订单。
    返回：字典，含 total（总额）和明细（如有分组）。
    """

② 参数设计（显式、有默认值）

参数名要直白，带合理默认值。Agent 传参时不需要猜。

# 参数设计示例：group_by 是可选的，filter_status 默认不过滤
def calc_gmv(df, filter_status=None, group_by=None):
    """..."""
    if filter_status:
        df = df[df["状态"] == filter_status]
    total = df["金额"].sum()
    if group_by:
        detail = df.groupby(group_by)["金额"].sum().to_dict()
        return {"total": float(total), "明细": detail}
    return {"total": float(total)}

③ 结构化返回（字典，不用 print）

返回一个干净的 Python 字典，Agent 可以直接解析。不要返回 DataFrame（模型不方便读），不要 print。

# ✅ 好：结构化字典
return {
    "total": 54321.0,
    "口径": "已完成订单",
    "明细": {"数码": 32000.0, "服饰": 12000.0, "食品": 10321.0}
}

# ❌ 差：print 出去，Agent 解析不了
print(f"GMV = {total}")

④ 错误反馈（异常时返回有意义的信息）

工具出错时不要静默失败，要返回明确的错误信息，让 Agent 知道「哪一步出了什么问题」。

# 反面教材：出了错 Agent 只看到空结果
def calc_gmv(df, filter_status=None):
    df = df[df["状态"] == filter_status]  # filter_status=None 时这行不会出错
    return {"total": df["金额"].sum()}

# 正确做法：显式校验，返回错误信息
def calc_gmv(df, filter_status=None):
    if "金额" not in df.columns:
        return {"error": "数据中没有'金额'列", "可用列": list(df.columns)}
    if "状态" not in df.columns and filter_status:
        return {"error": "数据中没有'状态'列，无法按状态过滤"}
    # ... 正常计算
⚠️ 最常见的错误：把清洗逻辑藏在工具内部。比如 calc_gmv 里默默 dropna() 了——Agent 不知道数据被删了行，结论里可能少算了。清洗要么在工具外面做，要么作为参数让用户控制。

三、实战：电商工具箱完整示例

以下是基于 UCI Online Retail 数据集（54万行UK电商订单）设计的工具箱。这个数据集的字段：

字段含义常见坑
InvoiceNo订单号以 C 开头的 = 退货单
StockCode商品编码部分是特殊编码（如 POST = 邮费）
Description商品名有缺失、有拼写不一致
Quantity数量退货单是负数
InvoiceDate开票日期需要 to_datetime 转换
UnitPrice单价有 0 值（免费赠品）
CustomerID客户ID约 25% 缺失——这是容错重点
Country国家主要是 UK
 
# ecommerce_toolkit/tools.py — 电商数据工具箱
# 贯穿数据集：UCI Online Retail（54万行，2010-12 ~ 2011-12）
import pandas as pd
from pathlib import Path

DATA_FILE = Path(__file__).resolve().parent.parent / "data" / "Online Retail.csv"


def load_data(encoding="utf-8"):
    """读取电商数据集，自动处理日期列。返回 DataFrame。
    用途：所有分析的第一步。返回前 5 行摘要供 Agent 快速了解数据。
    """
    try:
        df = pd.read_csv(DATA_FILE, encoding=encoding, dtype={"CustomerID": str})
    except UnicodeDecodeError:
        df = pd.read_csv(DATA_FILE, encoding="latin-1", dtype={"CustomerID": str})
    df["InvoiceDate"] = pd.to_datetime(df["InvoiceDate"])
    return {
        "行数": len(df),
        "列": list(df.columns),
        "CustomerID缺失率": round(df["CustomerID"].isna().mean() * 100, 1),
        "日期范围": str(df["InvoiceDate"].min()) + " ~ " + str(df["InvoiceDate"].max()),
        "国家数": df["Country"].nunique(),
        "前3行": df.head(3).to_dict("records"),
    }


def calc_gmv(df, exclude_returns=True, group_by=None):
    """计算 GMV（总成交金额）= Quantity × UnitPrice。
    用途：回答"总销售额"、"某品类/国家卖了多少钱"。
    口径：默认排除退货单（InvoiceNo 以 C 开头的行）。
    返回：{total, 口径, 明细}。
    """
    if "Quantity" not in df.columns or "UnitPrice" not in df.columns:
        return {"error": "数据缺少 Quantity 或 UnitPrice 列"}
    work = df.copy()
    work["Revenue"] = work["Quantity"] * work["UnitPrice"]
    if exclude_returns:
        work = work[~work["InvoiceNo"].astype(str).str.startswith("C")]
        note = "排除退货单"
    else:
        note = "包含退货单"
    result = {"total": round(float(work["Revenue"].sum()), 2), "口径": note}
    if group_by and group_by in work.columns:
        result["明细"] = {k: round(float(v), 2) for k, v in work.groupby(group_by)["Revenue"].sum().sort_values(ascending=False).items()}
    return result


def calc_avg_order_value(df, exclude_returns=True):
    """计算客单价 = GMV / 订单数（去重 InvoiceNo）。
    用途：回答"平均每单多少钱"、"客单价是多少"。
    注意：同一 InvoiceNo 包含多行商品，必须先按订单汇总再除。
    """
    work = df.copy()
    work["Revenue"] = work["Quantity"] * work["UnitPrice"]
    if exclude_returns:
        work = work[~work["InvoiceNo"].astype(str).str.startswith("C")]
    gmv = work["Revenue"].sum()
    n_orders = work["InvoiceNo"].nunique()
    if n_orders == 0:
        return {"error": "过滤后无有效订单"}
    return {
        "客单价": round(gmv / n_orders, 2),
        "GMV": round(gmv, 2),
        "订单数": n_orders,
    }


def calc_repeat_rate(df, exclude_returns=True):
    """计算复购率 = 下过 2 单及以上的客户占比。
    用途：回答"复购率"、"老客户占比"。
    口径：CustomerID 非空、排除退货后，按客户统计订单数，再算比例。
    """
    work = df.copy()
    if exclude_returns:
        work = work[~work["InvoiceNo"].astype(str).str.startswith("C")]
    work = work.dropna(subset=["CustomerID"])
    if len(work) == 0:
        return {"error": "过滤后无有效客户数据（CustomerID 全部缺失）"}
    orders_per_customer = work.groupby("CustomerID")["InvoiceNo"].nunique()
    total_customers = len(orders_per_customer)
    repeat_customers = len(orders_per_customer[orders_per_customer >= 2])
    return {
        "复购率": round(repeat_customers / total_customers * 100, 2),
        "总客户数": total_customers,
        "复购客户数": repeat_customers,
    }
💡 注意看：每个工具都做了三件事——①校验输入列是否存在（缺列就返回错误）、②清洗逻辑写在参数里可控（exclude_returns）、③返回值是干净字典。这就是 30 课「工具设计与结构化输出」在电商场景的落地。

🤔 小测

你写了一个 calc_gmv 工具，默认排除退货单。用户问："包含退货的话，英国的 GMV 是多少？" Agent 该怎么调用？

  1. calc_gmv(df, exclude_returns=True) —— True 就是包含退货
  2. calc_gmv(df, exclude_returns=False) —— False 表示不排除退货
  3. calc_gmv(df, include_returns=True) —— 传一个新参数
  4. calc_gmv(df[df["Country"]=="United Kingdom"]) —— 只需要过滤国家
点击展开答案与解析
答案：B。exclude_returns=False 表示不排除退货，即包含退货单。A 错：True 是排除退货，与需求相反。C 错：函数参数叫 exclude_returns，不能凭空换名字——参数名是 API 契约，改了就调不通。D 错：只过滤了国家，没有处理退货排除的问题——需求是「包含退货 + 英国」，两个条件都要满足。
