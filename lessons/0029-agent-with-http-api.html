🌐 接入真实 HTTP API 作为工具

第 0029 课 · P5 实战篇 实操课

🎯 本课目标：把 28 课的「mock 数据」替换成真实 HTTP API——让 Agent 通过网络调外部服务（天气、汇率、用电量、快递……）拿到真实数据。核心只多一件事：用 requests 发请求，包装成工具函数。骨架还是 28 课的 ReAct 循环。

从 mock 到真实：工具的本质是「函数」

28 课你写了一个 Agent，能调 4 个工具查台区电量。但那些数据是写死在 Python 字典里的——真实工作里，数据来自：

  • 公司的业务系统 HTTP API（最常见）
  • 公开数据接口（天气、汇率、股票、新闻）
  • 数据库（MySQL、PostgreSQL、MongoDB）
  • 内部文件服务（Excel/CSV 上传下载）

好消息：对 Agent 来说，这些全是「工具函数」，区别只在于函数内部做什么。HTTP API 工具就是用 requests 发个 HTTP 请求，把返回的 JSON 喂回 Agent。

📌 这节课的核心：你之前用 AI 写过不少调 API 的脚本（第 3 课 Hello World 调 DeepSeek、之后调各种外部 API）。今天学的是——把那个调 API 的 Python 函数注册成 Agent 的工具，让 AI 自己决定什么时候调。骨架和 28 课一模一样，只是工具函数内部从查字典变成发 HTTP 请求。

动手：调一个真实天气 API

我们用一个免费、无需注册的接口：wttr.in。浏览器打开 https://wttr.in/Beijing?format=j1 直接看 JSON。下面把它注册成 Agent 的工具：

# tools_http.py —— 真实 HTTP API 工具
import requests

def get_weather(city):
    """查询指定城市的当前天气"""
    try:
        resp = requests.get(
            f"https://wttr.in/{city}?format=j1",
            timeout=10  # 必加：别让程序卡死
        )
        resp.raise_for_status()  # 4xx/5xx 自动抛异常
        data = resp.json()

        # 只挑我们关心的字段返回给 AI，别把整个 200 行 JSON 塞过去
        current = data["current_condition"][0]
        return {
            "city": city,
            "temp_c": current["temp_C"],
            "desc": current["weatherDesc"][0]["value"],
            "humidity": current["humidity"]
        }
    except requests.Timeout:
        return {"error": f"请求 {city} 超时（10s）"}
    except requests.HTTPError as e:
        return {"error": f"HTTP 错误: {e.response.status_code}"}
    except Exception as e:
        return {"error": f"未知错误: {type(e).__name__}: {e}"}
💡 和 28 课 mock 工具的 3 个关键差异：
  1. 加 timeout=10：网络请求必加超时，否则对方服务器卡住，你这边无限等
  2. 加 raise_for_status()：4xx/5xx 自动转异常，比手动检查 status_code 干净
  3. 只返回关键字段：wttr.in 原始 JSON 有 200+ 行，只挑 4 个字段喂给 AI，省 token、降干扰

复用 28 课的 ReAct 骨架

把 28 课的 agent_react.py 复制一份，改三处：

# agent_http.py —— 改自 28 课的 agent_react.py
import json
from openai import OpenAI
from tools_http import TOOL_REGISTRY  # ← 改 1

client = OpenAI(api_key="sk-你的密钥", base_url="https://api.deepseek.com")

def run_agent(user_query, max_steps=4):
    messages = [{"role": "user", "content": user_query}]

    for step in range(max_steps):
        resp = client.chat.completions.create(
            model="deepseek-chat",
            messages=messages,
            tools=tools  # ← 改 2：用新的 tools 列表
        )
        msg = resp.choices[0].message

        if not msg.tool_calls:
            return msg.content

        messages.append(msg)
        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            print(f"  [step {step+1}] → {call.function.name}({args})")

            try:
                result = TOOL_REGISTRY[call.function.name](**args)  # ← 改 3
            except Exception as e:
                result = {"error": f"执行失败: {e}"}

            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": json.dumps(result, ensure_ascii=False)
            })

    return "（达到最大步数）"

if __name__ == "__main__":
    print(run_agent("今天北京天气怎么样？"))

看——主循环代码和 28 课 100% 一样，只改了 3 行（导入的 registry、tools 列表、TOOL_REGISTRY 调用）。这就是工程化的力量：新工具不写循环逻辑，只写函数。

⚠️ 调外网 API 的 3 个坑：
  1. timeout 必加：默认 requests 无超时，对方卡死你就死等
  2. 限流 / 鉴权：公司内部 API 大多有 token / IP 白名单，加在 headers= 里
  3. 字段清洗：外部 API 返回的字段又多又乱，只挑你需要的——既省 token 又减少 AI 干扰

🎯 本课核心结论：工具函数的实现方式（查字典 / 发 HTTP / 读数据库 / 读文件）对 Agent 来说没区别。你写好函数 + 写好 description，AI 都能调。区别只在你的函数内部怎么拿数据。这就是 28 课搭骨架、29 课换数据源的精髓。

小测答案：B。timeout=10 是调 HTTP API 的安全底线——没有它，对方服务器卡住时你的程序会无限等待，整个 Agent 直接死锁。A 错：原始 JSON 经常上百行，完整喂给 AI 既烧 token 又干扰推理；正确做法是在工具函数里挑字段，只返回 4-5 个关键字段。C 错：超时时长是工程参数，跟 AI 决策无关，AI 只决定「调不调工具」，不决定「底层怎么调」。D 错：HTTP 方法（GET/POST/PUT/DELETE）由 API 设计决定，不是「越复杂越好」——wttr.in 就是 GET。29 课的核心习惯：外部 API 调用必加 timeout + 异常处理 + 字段清洗，这三条是 35 课《评估与安全》的预演。
