二、毕业项目：三条硬标准

26 课那次「毕业项目」的标准是「解决一个真问题」。这次不一样——这次的产出要能拿给别人看，所以标准要硬三倍：

标准是什么意思怎么算过关
① 可展示 别人不用装 Python 也能看见结果 有一段输出记录 / 截图 / 图表；说得清「输入什么、输出什么」
② 可部署 别人 clone 下来能跑 按 36 课六条检查清单走一遍，换目录跑通，不报错
③ 数字对得上 结论不是「看起来合理」，是可复核 有固定测试问题集，每个答案都有独立算法复算过的标准值
⚠️ 第三条是分水岭。市面上大量「AI 数据分析」作品停在第一条——界面好看、结论华丽，但没人能确认数字对不对。你从 34 课开始就带着 verify 走，这是你比同岗位其他候选人更硬的地方。面试时这一条要主动讲。

三、选题：主推「电商订单分析 Agent」

脚手架我已经按这个选题搭好了（下面第四节），所以推荐你直接用它起步——理由不是省事，是它同时对上三件事：

  • 对上后面的路：38～45 课（P6）会把电商工具箱一路做到求职作品主体，43 课（数据洞察 Agent）就是它的升级版。今天这一版是 v1，别扔。
  • 对上你的定位：你的求职锚点是数分 + 能落地 Agent 的复合位。这个项目正好把两条线焊在一起——分析能力（pandas/口径）和工程能力（Agent 架构）同一件作品里都有。
  • 数据脱敏：示例数据是 60 行模拟订单，不含任何公司真实业务数据——可以放心放 GitHub，这是硬约束。

如果你更想用自己工作里的真问题，也可以，只要注意一条：把业务数据换成模拟数据再放仓库（35 课安全闸）。选题换不换，三条硬标准不变。

四、脚手架：lessons/code/capstone_kit/

这不是「给你抄的答案」，是骨架——能跑、能读、留了明显的改造口。目录：

capstone_kit/
├── main.py            入口：提问 / --selftest 离线自测
├── agent/tools.py      五个数据工具（含 verify 核验卡口）
├── agent/core.py       ReAct 循环 + 步数预算 + 运行留痕
├── tests/eval.py       固定测试问题集 + 标准答案
├── data/orders.csv     示例电商订单（60 行）
├── runs/               每次提问的过程记录（JSON）
├── ARCHITECTURE.md     架构图 + 设计决策
├── README.md           三步跑起来
└── requirements.txt / .env.example / .gitignore

本课推送前，我从临时目录实跑了一遍离线自测（验证「换目录也能跑」，36 课的那条）：

== 固定测试问题集（离线，不调模型） == [PASS] Q1 各品类销售额(剔除退款) [PASS] Q1b 销售额合计独立复算 [PASS] Q2 各渠道订单量(全部) [PASS] Q3 各渠道退款率 [PASS] Q4 不同订单号数(nunique) [PASS] Q5a verify 能复算正确值 [PASS] Q5b verify 出错时返回失败而非崩溃 结果：7 通过 / 0 失败
💡 注意这个设计：--selftest 不需要 API key。它一次都不调大模型，纯 pandas 跑——因为要验证的是数据层口径对不对，这跟模型无关。模型那层的验证，是用同一套问题去问 Agent，看它的回答是否落在标准值上（35 课的思路）。先确定「工具算得对」，再调模型——这个顺序本身就是工程判断力。

五、你的任务：四道关，逐个过

第 1 关 · 跑通（30 分钟，今晚就能做完）

把 capstone_kit/ 复制到你的项目目录，装依赖，跑 --selftest，看到 7 个 PASS。再配好 key，问它一句「各品类销售额是多少（剔除退款）？」，看它自己调工具、复算、给结论。

过关标志：runs/ 里出现一个 JSON，打开能看到它每一步调了什么工具、传了什么参数。

第 2 关 · 换数据（1 晚）

把你自己的数据（脱敏后）放进 data/，改 agent/tools.py 顶部的 DATA_FILE，同步改 tests/eval.py 的问题和标准答案——标准答案必须你自己手算一遍填进去，不能用 Agent 的输出当答案（那是自证，35 课的坑）。再跑一次 selftest。

过关标志：换了数据之后 selftest 依然全 PASS，且你能说清每一道题的口径。

第 3 关 · 改造（1-2 晚，这一关才是你的作品）

从下面挑至少两件做（做三件就够讲三个面试故事了）：

  • 把 verify 从「提示词要求」改成「代码硬约束」：如果 Agent 最后一步没调 verify，就强制再走一轮。做完你会发现——代码约束比跟模型讲道理可靠。
  • 加一个「口径澄清」：问「8 月销售额多少」时，Agent 必须先声明自己用的口径（含/不含退款），且这个问题它答不上来时要说「需要你确认」而不是硬答。
  • 加一个可视化工具：用 33 课的 pyecharts 出一张交互图，存到 runs/ 里一起交付。
  • 加一个工具：比如「按日期看趋势」（groupby('日期')），走 30 课的流程：写函数 → 定参数 Schema → 注册。

过关标志：改造后的行为有留痕可查——runs/ 里的记录能证明新逻辑真的生效了。

第 4 关 · 发布（1 晚）

照 36 课六条检查清单过一遍，建一个 GitHub 仓库推上去——README 第一屏就要写出：这是什么、解决什么问题、三步怎么跑、效果长什么样。想要个网址就上 Streamlit Community Cloud（记得先自测国内能不能打开）。

过关标志：「假装自己是别人」——换个目录 clone 下来，严格照 README 从零跑通。报的每一个错都是你漏掉的检查项。

六、验收清单

四关过了以后，用这六条自查（前三条对应本课三条硬标准）：

  • 可展示：能给人看一段真实运行的完整过程（不是「我做了个东西」）。
  • 可部署：换目录 clone 后，照 README 一条命令跑通。
  • 数字对得上：固定测试问题集全 PASS，且标准答案是你手算的。
  • 有留痕：runs/ 里的过程记录完整，中间产物看得见。
  • 会容错：没 key、文件缺失、列名不对时，给清晰提示而不是崩溃闪退。
  • 说得清：面试官问「你为什么不用 pandasai 这类现成方案」，你有答案（32 课的批判 + 34 课的核验卡口）。
📝 简历怎么写这个项目（一句话模板）：
「独立开发数据分析 Agent（Python / DeepSeek API / 自研 ReAct 循环）：自然语言提问 → 自动选工具算指标 → 出结论前用独立算法复算，并留存全流程可审计记录；配套固定测试问题集保证数据口径一致。」
这句话里最有价值的是加粗那半句——它把「会调 API」和「知道 AI 会自信地错，所以设计了核验」区分开了。

小测答案：B。固定测试问题集 + 独立复算——它证明的不是「它能跑」，而是「它的结论可以被检验」。这正是 34/35 两课的核心增量，也是本项目区别于多数 AI 数分作品的地方。
A 错：视频只能证明「有一次跑得很流畅」。面试官无法判断那次结果是碰巧对还是真的对——演示视频和「可复现」是两回事。
C 错：说模型版本是最弱的一种证明。换个模型你的项目还成立吗？成立，那就说明模型不是重点；不成立，那说明项目本身没有壁垒。
D 错：给源码是必要的（可部署标准要求），但「让面试官自己读懂」不算展示。你的 README 和运行记录应该让他 3 分钟就能看懂，而不是读完 150 行代码才明白你在干什么。
