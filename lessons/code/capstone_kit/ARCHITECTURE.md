# 架构说明：一个 Agent 项目的完整结构

## 全景图

```
用户自然语言提问
        │
        ▼
┌─────────────────┐
│  ReAct 循环      │  agent/core.py   （28 课）
│  最多 8 步，每步 │
│  ：大模型决策    │
│  → 调工具 → 看结果│
└──────┬──────────┘
       │ 需要数据时
       ▼
┌──────────────────────────┐
│  工具层（都是普通 Python） │  agent/tools.py（31/34 课）
│  profile  数据画像         │
│  group_sum 分组求和        │
│  count_distinct 去重计数  │
│  verify    独立复算        │
└──────┬───────────────────┘
       │ 只读
       ▼
┌─────────────────┐     ┌────────────────────┐
│ data/orders.csv │     │ runs/ 过程留痕     │
│ （原数据只读）   │ ──▶ │ 每次运行一个文件   │
└─────────────────┘     └────────────────────┘
```

## 五个工具（34 课）

| 工具 | 干什么 | 为什么需要它 |
|---|---|---|
| `profile` | 开头自动读一次：行数、列名、类型、状态取值、前3行 | 模型不读全表，只读压缩后的「数据画像」，省 token、先懂数据再分析 |
| `group_sum` | 按列分组对金额求和，可按状态过滤 | 算「各品类销售额」这类指标的主力 |
| `group_count` | 按列分组计数（订单量） | 算退款率需要两个数：分子（退款单数）、分母（全部单数） |
| `count_distinct` | 对某列去重计数 | 「多少个不同 X」只能用 nunique，count 会把重复算进去 |
| `verify` | 用**另写**的独立 pandas 表达式复算同一个数 | 28→34 课的核心增量：出结论前交叉验证，防止 Agent 自信地错 |

## 设计决策（每条都有出处）

1. **原数据只读**。工具层只有读操作，没有 update/delete。原数据是基准，不可变（09-02 讨论定论）。
2. **核验是内置步骤，不是可选后缀**。系统提示词里写「出最终数字结论前必须 verify」——但注意，代码里硬约束比提示词约束强，这留给你当动手任务。
3. **过程落盘留痕**。每次提问在 `runs/` 生成一个 JSON，完整记录每一步：调了什么工具、传的什么参数、看到什么结果、最后给了什么答案。这是 35 课「固定测试问题集」的运行底座，也是你简历项目「中间产物可见」的证据。
4. **步数预算**。循环上限 8 失控消耗防呆（35 课「敢说不知道」的工程实现之一）。
5. **key 不出代码**。代码只 `os.environ.get`，值在 `.env`，已 gitignore。
6. **数据字典缺位的处理**：系统提示词要求 Agent 遇到口径不清的列/取值，明说「需要你确认口径」，而不是瞎猜——「敢说不知道」。

## 你要动的地方

- **换数据**：改 `agent/tools.py` 顶部 `DATA_FILE`，列名不同就同步工具描述和 eval 标准答案。
- **加工具**：在 `tools.py` 加一个普通函数，再到 `core.py` 的 `TOOL_REGISTRY` 和 `tools` 规格列表里注册即可。
- **硬约束 verify**：把「最后一步必须是 verify」从提示词约束改成代码检查（若最后一个工具调用不是 verify，强制再走一轮）。
