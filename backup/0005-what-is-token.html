📚 第 5 课 · 什么是 Token？

2026-06-27 · 预计阅读 4 分钟 · 课程 0005

一句话讲清

Token 是 AI 模型「读」文字的最小单位。 就像我们数文章长度用「字」，AI 用「token」。你的 prompt 被拆成 token 送进模型，模型的回复也是一个一个 token 生成的。Token 直接决定两件事：你花多少钱和AI 能记住多少。

Token 长什么样？

把一句话丢给 tokenizer（分词器），它会切成这样：

语言原文切分结果（示意）Token 数
英文 Hello, world! Hello | , | world | ! 4
中文 你好世界 你好 | 世界 2
中文长句 请帮我总结这份合同。 请 | 帮 | 我 | 总结 | 这份 | 合同 | 。 7
🧮 经验公式
  • 英文：1 个 token ≈ ¾ 个单词（约 4 个字符）
  • 中文：1 个 token ≈ 1~2 个汉字
  • 代码：每个运算符、关键字都可能独立成 token

重要：token ≠ 字，也 ≠ 词。常见的词如「the」「是」是 1 个 token，生僻词或 emoji 可能吃掉多个 token。标点也算！

Token 为什么重要？——三个现实影响

1️⃣ 计费：你按 token 付钱

调用 DeepSeek API 时，你为 输入 token（你的 prompt）+ 输出 token（AI 的回复） 付钱。
DeepSeek 当前定价（截至 2026 年 6 月）：

输入（每百万 token）输出（每百万 token）
DeepSeek-V3¥2¥8

来源：DeepSeek API 定价页

发一条 500 token 的问题、收到 1000 token 的回答，成本约 ¥0.01——几乎免费，但 积少成多。

2️⃣ 上下文窗口：AI 一次能「看到」多少

模型的上下文窗口（context window）以 token 为单位。DeepSeek-V3 的上下文窗口是 128K token——约等于一本 200 页小说的量。
超过这个上限？AI 就「忘掉」最早的内容了。

3️⃣ 对话记忆：为什么 AI 会「断片」

每次你回复，赫默会把你和 AI 的整个对话历史重新发给模型。对话越长 → token 越多 → 接近上限时，最早的消息被截断。这就是为什么聊久了 AI 似乎「忘了」开头说了什么。

看一眼代码：怎么数 token？

# 用 DeepSeek 估算 token 数（不实际发请求）
from openai import OpenAI

client = OpenAI(
    api_key="sk-your-key",
    base_url="https://api.deepseek.com"
)

# 这个 prompt 大概多少 token？
prompt = "请帮我总结一下这份合同的核心条款。"
# DeepSeek 目前不直接提供 tokenizer endpoint，
# 但可以在实际调用后从 response.usage 看到 token 统计

response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": prompt}],
    max_tokens=100
)

print(f"输入用了 {response.usage.prompt_tokens} token")
print(f"输出用了 {response.usage.completion_tokens} token")
print(f"一共 {response.usage.total_tokens} token")
📊 输出示例
输入用了 12 token
输出用了 38 token
一共 50 token

usage 对象就是你的「账单明细」——每次调用都能看到花了多少 token。

❓ 小测

🔍 关于 Token，以下哪项说法是正确的？
  1. A. 一个汉字一定等于一个 token
  2. B. Token 只计算输入，输出不收费
  3. C. Token 同时决定费用上限和 AI 一次能记住多少
  4. D. 用英文比中文更省 token，因为英文单词短
✅ 正确！Token 是计费单位和上下文窗口单位的统一度量。
❌ 再想想：token ≠ 字，且输入输出都收费。英文 1 token ≈ 0.75 个单词，中英文的 token 效率差不多。
