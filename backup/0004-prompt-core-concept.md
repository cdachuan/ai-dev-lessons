# 0004 · Prompt 核心概念

**日期**：2026-06-26
**课程**：0004 · 什么是 Prompt？
**状态**：已交付

## 关键洞察

1. **Prompt 不是「高级技巧」，而是「日常基本功」** —— 用户每天用赫默聊天，其实已经在写 prompt。这课的核心是把隐性的日常行为显性化，让用户意识到「我一直在写 prompt，现在可以写得更好」。

2. **System vs User 的分层结构** —— 这是编程向 prompt 工程转化最关键的一个认知跳跃。System prompt 设定「角色和规则」（一次设定、整个对话生效），user prompt 提出「具体任务」（每次不同）。这个模式可以复用：给赫默设定身份 → 再问问题。

3. **编程基础和 prompt 的关系** —— 用户编程基础弱，但 prompt 工程几乎不需要懂代码。代码层面的 `messages` 列表结构在上一课（0003）已经见过，这课侧重语义而非语法。System/user 的概念即使不写代码，在赫默 UI 里也能用（手动在对话开头说「请你扮演……然后回答我的问题」）。

4. **「增量胜利」的设计** —— 这课没有代码，但用户学完就能立刻用上：下次在赫默提问时，先给一句 role setting（system），再问具体问题。5 分钟内见效。
