# 0007 · Tool Calling 核心概念

**日期**：2026-06-29
**课程**：0007 · 什么是 Tool Calling？
**状态**：已交付

## 关键洞察

1. **「模型只有嘴，Tool Calling 是它的手」**——这是本课最核心的认知跳跃。上节课用户理解了 Agent 循环（Think → Act → Observe），但不知道 Act 具体怎么实现。Tool Calling 给出了答案：模型输出结构化 JSON 指令，程序负责执行。这个区分让用户不再对「AI 调用工具」感到神秘。

2. **JSON 是模型和程序之间的「契约语言」**——模型不真的「做」任何事情，它只是按照训练时学会的格式输出 JSON。这个 JSON 描述了「需要调用什么工具 + 带什么参数」。程序（赫默、或者你自己写的代码）负责解析 JSON 并实际执行。理解这个分工后，用户就能明白 AI 应用的架构模式。

3. **工具的「说明书」由你写**——用户在代码示例中看到 `tools` 参数列表，每个工具都有名称、描述、参数定义。这意味着 AI 能做什么完全由你控制。想让它能查数据库？加一个工具定义就行。想让它在特定场景下才能调某工具？从 prompt 或 tool 定义里限定。这个「可扩展」的认知对后续写真实脚本（0008）至关重要。

4. **赫默的每个动作都可复现**——用户每天看到赫默搜索、读文件、执行代码，现在知道这不是模型自带的能力，而是赫默开发者注册的工具。用户自己写的 Python 脚本也可以做同样的事（0008 会动手实现）。

## 待观察

- 用户看了 JSON 格式的工具定义后，可能会觉得「好复杂」——0008 课要从最简单的单工具脚本开始，降低认知门槛
- 必须强调 Tool Calling ≠ Function Calling（OpenAI 把类似能力叫 Function Calling，DeepSeek 叫 Tool Calling，但核心都是模型输出结构化指令）——术语对照需要写在参考文档里
- 用户是否理解「工具定义」和「工具实现」的区别？定义是告诉模型有这个工具，实现是实际执行的代码——这两个可以分开写，也可以不在同一处
