第 7 课 · 什么是 Tool Calling？

2026-06-29 · 阅读时间 5 分钟

上节课我们学了 Agent——它能自动思考、调用工具、完成任务。但你有没有想过一个关键问题：AI 模型只会生成文字，它是怎么「调用工具」的？

答案就是 Tool Calling（工具调用）。它是让 AI 从「聊天机器人」变成「办事机器人」的核心技术。今天我们就把它彻底讲明白。

问题：AI 只有一张嘴

想象一下：你让一个助手「帮我查一下明天的天气」。助手答应了，但他没有手机、没有电脑、不能出门——他只是一张嘴。LLM 就是这个状态：它能理解你的问题，能回答，但它「手」上什么也没有。

那赫默是怎么帮我们查天气、读文件、搜网页的？

答案是：模型不直接做这些事，它告诉你「你应该做这些事」——然后由程序（赫默自己）来执行。

Tool Calling 的核心机制

普通的 API 调用，你问一句，模型回一段文字：

你  →  "明天北京天气怎么样？"
模型  →  "抱歉，我没有实时数据，无法查到天气信息。"

但用了 Tool Calling 之后，模型的回答会变成结构化指令：

你  →  "明天北京天气怎么样？"
模型  →  {
    "tool": "get_weather",
    "params": {
      "city": "北京",
      "date": "2026-06-30"
    }
  }

模型输出的不再是自然语言，而是一个 JSON 指令——告诉程序：去调 get_weather 这个函数，参数是"北京"和"明天"。

程序收到 JSON 后：

  1. 解析指令：知道要调哪个工具、传什么参数
  2. 执行工具：调用天气 API，拿到结果
  3. 结果回填：把天气数据送回模型
  4. 最终回答：模型基于真实数据告诉你「明天北京 25°C，多云」

💡 一句话总结：Tool Calling = 模型输出「做事指令」（JSON），程序负责执行。

你每天都在用 Tool Calling

赫默的所有「非聊天」能力都靠 Tool Calling：

  • 搜索网页 → 模型输出 {tool: "web_search", query: "..."}
  • 读文件 → 模型输出 {tool: "read_file", path: "..."}
  • 写文件 → 模型输出 {tool: "write_file", path: "...", content: "..."}
  • 执行代码 → 模型输出 {tool: "execute_python", code: "..."}

你每次看到赫默在「正在搜索…」「正在读取…」，背后都是一个 Tool Calling 流程在跑。

和 Agent 循环的关系

上节课讲的 Agent 循环（Think → Act → Observe） 中，Act 这一步就是用 Tool Calling 实现的：

  用户提问
      ↓
Think: "这个需要查天气"
      ↓
Act: 模型输出 JSON → 程序执行 get_weather()
      ↓
Observe: 天气数据返回给模型
      ↓
Think: "好了，现在我有数据了，回答用户"
      ↓
Act: 模型输出最终回答

看懂了吗？Tool Calling 就是 Agent 循环中「动手」的那一步——Agent 是整个系统，Tool Calling 是它「伸手拿东西」的机制。

代码看一眼

用 DeepSeek API 调 Tool Calling 的真实代码大概长这样（不用全懂，看个样子）：

import requests

# 定义工具
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "获取城市的实时天气",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string"}
            },
            "required": ["city"]
        }
    }
}]

# 发送请求，告诉他你有哪些工具可以用
response = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "deepseek-chat",
        "messages": [{"role": "user", "content": "北京天气如何？"}],
        "tools": tools           # ← 告诉模型你有这些工具可用
    }
)

print(response.json())
# 模型中返回的不是文字，而是工具调用指令

关键就两件事：

  1. 告诉模型你有什么工具（名称、参数说明）
  2. 模型决定要不要用——它会自己判断「这个问题需不需要工具」，需要就输出 JSON 指令

为什么这很重要？

理解 Tool Calling 之后，你就能明白：AI 应用的能力边界，不取决于模型，而取决于你给了它什么工具。

给模型一个「搜索工具」，它就能查资料。
给模型一个「读数据库工具」，它就能做数据分析。
给模型一个「发邮件工具」，它就能自动回复客户。

这就是为什么赫默可以不断添加新能力——每次加一个新工具就行了。模型不需要重新训练，它本来就会「用」工具，只是需要你告诉它有哪些工具可选。

❓ 小测：

Tool Calling 中，AI 模型返回的「做事指令」是什么格式？

A. 自然语言的句子，比如「帮我查天气」

B. ⭐ JSON 格式的结构化数据

C. 图片格式

（答案是 B。模型输出 JSON，程序执行，结果回填模型再输出最终回答。）
