# 0002 · API 核心概念认知

**日期**：2026-06-24
**课程**：0002 · 什么是 API？
**状态**：已交付

## 关键洞察

1. **API 的「服务员」类比非常有效** —— 用户不需要理解 HTTP、JSON 等技术细节，只需理解 API 是「中间人」角色。这个类比能帮用户直观理解：为什么调用 API 比手动操作高效。

2. **赫默本身就是 API 客户端的例子** —— 用户每天都在用 API，只是不知道。把「每天用的东西」和「新的概念」关联起来，降低认知门槛。

3. **API 的「批量处理」能力是用户核心动力** —— 用户是项目助理，经常需要处理文件/报告。手动一条条粘到赫默里 vs 一个脚本批量处理，后者正是用户想学的东西。

4. **API Key 的安全意识需要提前强调** —— 用户编程基础弱，可能不理解密钥不能公开。需要在这课埋下安全意识的种子，避免后续实操时误传密钥。

## 待观察

- 用户对 JSON 格式的接受程度——虽然只是展示，但需要确认用户是否理解了这种「键值对」结构
- 用户是否理解「自己调 API」和「用赫默」的差异——这决定了后续实操课的节奏
