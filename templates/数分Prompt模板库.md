# 数分Prompt模板库（配合LLM做分析时的可复用句式）

> 核心原则：给例子比给形容词管用；数字由代码算，模型只解释数字；先口径后结论。

## 一、需求拆解类

**模糊需求 → 分析框架**
```
我的业务问题是：{原话}
请把它拆解成可量化的分析问题清单（每个问题标出：需要的字段/指标口径/可能的结论维度），
只出清单不要开始分析，我确认后再继续。
```

**明确口径**
```
本次分析统一口径：
- GMV = 数量×单价，退货（数量<0或发票号C开头）记负收入，不删行
- 客单价 = 净GMV ÷ 有购买行为的发票数（退货单不算单）
- 时间窗 = {起止}，剔除不完整月份并标注
以下所有计算都按此口径，如遇字段缺失请停下问我，不要自行假设。
```

## 二、SQL/代码生成类

**SQL生成**
```
表结构：{DDL或字段说明}
需求：{业务问题，含口径}
请生成 duckdb SQL。要求：
1. 只用 SELECT（只读）
2. 关键步骤加注释说明对应口径哪一条
3. 同时给出你预期结果的大致形态（几行/什么量级），用于我核验
```

**结果核验（verify句式，最重要的一个）**
```
这是分析代码的输出结果：{结果}
请用另一种计算路径（不同函数/先汇总再拆分）独立复算同一指标，
两边一致才输出结论；不一致请报告差异，不要强行解释。
```

## 三、解读与汇报类

**数字 → 结论**
```
计算结果（由代码产出，保证算术正确）：{数据表}
请基于它写3条以内发现，每条=数字+对比+业务含义。
禁止编造表里没有的数字；不确定的归因标"待验证"。
```

**给领导的版本**
```
把以下分析压缩成汇报版：第一句给结论，然后≤3条支撑，
最后一条给行动建议（含预期收益）。字数≤200。
{分析内容}
```

## 四、反AI腔检查
```
检查以下文字：删掉"赋能/抓手/闭环/全面/深入"类空词，
每个观点必须有数字或例子支撑，没有的删掉。
{文字}
```
