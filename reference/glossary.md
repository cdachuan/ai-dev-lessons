|------|------|------|----------|

| API | Application Programming Interface | 应用程序接口，让两个程序互相通信的约定 | 0002 |

| SDK | Software Development Kit | 软件开发工具包，把 API 调用封装成更方便的代码库（如 `pip install openai`） | 0003 |

| RAG | Retrieval-Augmented Generation | 检索增强生成：先搜索相关文档，再让模型基于文档回答 | 0009 |
| Function Calling | 函数调用 | 让 AI 模型决定调用哪个函数并填入参数的能力 | 0010 |
| f-string | 格式化字符串 | Python 中用 `f"文本{变量}"` 语法把变量值嵌入到字符串中的写法 | 0008 |
| open() | — | Python 内置函数，用来打开文件；常用模式 `open("路径", "r", encoding="utf-8")` | 0008 |
| sys.argv | — | Python 系统参数列表；`sys.argv[0]` 是脚本名，`sys.argv[1]` 是第一个命令行参数，用于让脚本接受外部输入 | 0011 |
| openpyxl | — | Python 第三方库，专门用来读写 `.xlsx` 格式的 Excel 文件；需先 `pip install openpyxl` 安装 | 0012 |
| Workbook | 工作簿 | Excel 文件本身，包含一个或多个工作表（sheet），在 openpyxl 中用 `load_workbook("文件名")` 加载 | 0012 |
| Worksheet | 工作表 | Excel 文件中的一个标签页（默认用 `.active` 获取当前打开的那个） | 0012 |
| for 循环 | for loop | Python 中「对每个元素做同一件事」的写法；`for row in rows:` 表示「对 rows 里的每一行，执行下面的代码」 | 0012 |

| pandas | — | Python 数据分析库，用表格（DataFrame）处理数据； 读文件、 分组聚合 | 0031 |
| DataFrame | — | pandas 里的二维表格数据结构，类似 Excel 表，有行和列 | 0031 |
| groupby() | 分组聚合 | pandas 方法：按某列分组后对目标列做统计（sum/count/mean），口诀「按谁分+对哪列+怎么算」 | 0031 |

| pivot_table | 透视表 | pandas 方法：二维交叉汇总（行=类别，列=月份，值=指标），groupby 的二维版 | 0031 |

| 缺失值 | 缺失值 | 表格里空着的单元格（NaN）；用 isna() 查看、dropna() 删行、fillna() 填默认值 | 0031 |
| 部署 | Deployment | 让程序在别人的机器上、或一台别人能访问的机器上跑起来；本质是补齐依赖/配置/入口三样 | 0036 |
| 环境变量 | Environment Variable | 操作系统层面存放的键值对，程序用 `os.environ.get("键名")` 读取；密钥的正确存放位置 | 0036 |
| 依赖清单 | requirements.txt | 列出项目用到的第三方库的文本文件，别人靠它一条命令装齐环境 | 0036 |
| 入口文件 | Entry Point | 别人该从哪个文件启动整个程序（如 `python main.py`）；README 里必须写明 | 0036 |
| Secrets | — | 托管平台（如 Streamlit Community Cloud）提供的密钥保管配置，等价于云端的 `.env`，代码用 `st.secrets` 读 | 0036 |
| .gitignore | — | 告诉 git「哪些文件永远不要提交」的清单，用来挡住 `.env` 和真实业务数据 | 0036 |
| 核验卡口 | Verify Gate | 出结论前用**独立算法**复算同一个数的强制步骤，用来防「自信地错」；口径相同、写法必须不同 | 0034 |
| 可复现仓库 | Reproducible Repository | 别人 clone 后照 README 一条命令跑通的仓库（依赖/配置/入口三样齐备）；成本 0 元、求职价值最高的一级交付 | 0037 |
| 工作流 | Workflow | 路径由开发者**预先在代码里定好**的多步流程，模型只在单点做判断；与 Agent 相对 | 0038 |
| Agent | Agent | 路径由**模型自己边做边定**，代码只负责提供工具；与工作流相对（本课的区分口径） | 0038 |
| 提示链 | Prompt Chaining | 把任务拆成固定顺序的多步，上一步的输出作为下一步的输入 | 0038 |
| 路由 | Routing | 先判断输入属于哪一类，再交给对应的处理分支 | 0038 |
| 并行化 | Parallelization | 多个互不依赖的子任务同时执行，最后汇总（或同一问题多套判断投票） | 0038 |
| 编排者-执行者 | Orchestrator-Workers | 由模型动态拆解任务、分派给子任务、再汇总的模式；子任务数量不预设 | 0038 |
| 评估者-优化者 | Evaluator-Optimizer | 一个模型产出、另一个按标准挑错、循环到达标的结构；与核验卡口同一思想 | 0038 |
| 上下文膨胀 | Context Bloat | ReAct 循环中每步结果都追加进 `messages`，导致上下文越滚越大、模型被自己的中间产物淹没 | 0038 |
| 留痕 | Trace | 把 Agent 每次运行的工具调用、参数、结果、最终答案完整落盘，供事后审计与复现 | 0037 |
