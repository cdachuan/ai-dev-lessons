# AI 应用 / Agent 领域地图

> 这不是知识清单，是**判断尺**。每条共识/争议都标了"用在哪、学到什么程度算够"。

---

## 一、五个公认思维模式（5 共识）

> 满足这五条 → 大方向不会跑偏。违反任意一条 → 项目大概率烂尾或失控。

### 1. 能力 - 成本 - 延迟三角
- **核心**：任何技术选型都在这三者间找位置。GPT-4o 强但贵且慢，DeepSeek 便宜快但能力边界窄，本地小模型 0 成本但能干的活有限
- **判准**：说不出"为什么不用 X 而用 Y"的三选一取舍，就没真懂
- **学到位标志**：能针对一个具体场景列出 2-3 个候选方案，量化对比

### 2. 确定性来自结构，不来自聪明
- **核心**：Prompt 调优撞墙 = 该改架构了（pipeline、工具、状态机），别在文字里继续磨
- **判准**：能区分"prompt 层的边界"和"架构层的边界"
- **反例**：用 200 行 system prompt 试图"教育"模型按规矩做事，本质是拿文字当代码用

### 3. 评测先于实现
- **核心**：能写测试集 = 想清楚了"做什么"；没评测 = 还在凭感觉
- **三种测试集**：eval set（功能）、golden set（输出质量）、benchmark（横向对比）
- **判准**：动手前能列出 5-10 个"必须答对"的固定问题

### 4. 失败是常态不是异常
- **核心**：tool call 必失败、模型必胡说、上下文必超——按"必坏"设计，不按"应该能成"设计
- **必做三件事**：超时、重试、兜底回复
- **判准**：review 代码时主动找"如果这里失败会怎样"

### 5. 可观测 > 优雅
- **核心**：能看清系统每一步在干什么，比代码漂亮重要十倍
- **三件套**：日志、trace、replay
- **判准**：出问题能在 5 分钟内定位到"哪一步、哪条输入、哪个模型版本"

## 二、三个真争议（3 争议）

> 记住：争议没有"标准答案"，但有"我站哪边 + 为什么"。死记某一方答案 = 没学。

### 争议 1: Prompt Engineering 有没有未来

| A 方：死了 | B 方：没死 |
|----------|----------|
| 模型能力上来后 prompt 是过渡手艺 | in-context 永远是控制模型的唯一手段 |
| 结构化（function calling / JSON Schema / 工具）才是终局 | 差的 prompt 能浪费 10× token 和准确率 |
| 没有人靠写 prompt 拿到"长期不可替代"的能力 | fine-tuning / RLHF 本质也是另一种 prompt 工程 |

**站哪边的判据**：
- 做 to C 工具、追求可控性 → 倾向 A
- 做研究/写作助手、需要灵活引导 → 倾向 B
- **正解往往是**：A 用于生产链路，B 用于探索阶段

### 争议 2: Agent 该 planning 还是 reacting

| A 方：先规划再动手 | B 方：边干边想 |
|------------------|--------------|
| ReAct 跑偏代价大（API 钱、幻觉、副作用） | planning 不可靠，model 自己的 planning 比手写 heuristic 强 |
| 复杂任务必须有 plan，否则步骤乱 | 让它边干边想 + 重试 + 回滚，更鲁棒 |
| 适合：多步操作、外部副作用大、钱敏感 | 适合：探索性任务、答案空间开放 |

**站哪边的判据**：
- 钱 + 副作用敏感 → A
- 灵活 + 可重试 → B
- **正解往往是**：A 框主干，B 处理分支

### 争议 3: RAG 是不是终局

| A 方：是 | B 方：不是 |
|--------|----------|
| 没有 RAG 就没有私有知识、时效性、可控性 | RAG 是补丁，检索本身就是信息损失 |
| fine-tuning 贵且脆，更新慢 | 真解：长上下文 + 模型原生记忆 + 知识图谱 |
| 适合：文档问答、企业知识库 | 适合：超长上下文已成为标配（128K+）的场景 |

**站哪边的判据**：
- 数据频繁更新 + 必须可控 → A
- 知识静态 + 上下文够长 → B
- **正解往往是**：A 做主力，B 做长尾

## 三、怎么用这份地图

| 你在做 | 先查 |
|--------|------|
| 接到新需求，先选方案 | 共识 1（三角取舍） |
| Prompt 调不动了 | 共识 2（改结构） |
| 写 Agent 之前 | 共识 3（先有评测） |
| Code review | 共识 4（找失败点） |
| 出问题排查 | 共识 5（可观测） |
| 听到一个"绝对正确"的行业观点 | 查 3 争议（站哪边？为什么） |

## 四、扩展规则

- **新主题进来**：先填"5 共识"再填"3 争议"——找不到 3 个争议 = 主题太浅或没入门
- **共识/争议要标时间和来源**：AI 领域 6 个月翻一次天，2025 年的"共识"在 2026 可能是争议
- **不维护就删**：过时共识比没有共识更危险（误导新人）
