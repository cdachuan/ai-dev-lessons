# 0005 · 读文件 + API 总结脚本

**日期**：2026-07-03

**状态**：已交付

## 关键洞察

1. **「三步流水线」模式是 AI 脚本的通用骨架** —— 读文件 → 调 API → 输出结果。这个模式不只适用于总结，任何「处理本地数据 + AI 加工」的任务（翻译、审核、分类、提取信息）都复用同一结构。学到的是模式而非单一脚本。

2. **f-string 是 prompt 模板化的入门** —— `f"请总结：{content}"` 这种写法让用户直观理解「prompt 可以动态拼接」。这比手动拼接字符串更安全、更可读，也是后续 prompt 模板化的基础（比如把 system prompt 和 user prompt 分开写，内容用变量注入）。

3. **open() 的 encoding 参数是新手最容易忽略的坑** —— 中文环境下文件编码不统一（UTF-8 vs GBK），如果不指定 encoding，Windows 可能报错。这个细节需要在课程里明确强调，否则用户第一次运行时就会卡住。

4. **从「手动复制粘贴」到「脚本自动化」是认知转折点** —— 之前用户用赫默处理文件是手动操作；现在是一行 `python summarize.py` 完成。这个转折让「自动化」从概念变成了可触摸的体验。Mission 中的「自动化文书处理」直接对齐。

## 待观察

- 用户是否真的会动手创建文件并运行脚本——如果没运行，下次课可以设计一个「运行验证」的环节
- 用户对 Python open() 的理解程度——如果没接触过文件操作，可能需要额外解释路径概念（绝对路径 vs 相对路径）
- 如果用户尝试处理大文件遇到 token 超限，需要及时引入 RAG 课程（0009）
