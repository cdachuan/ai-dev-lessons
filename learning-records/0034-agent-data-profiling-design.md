5. **五项必备能力**（从死法反推）：
   | 死法 | 能力 | MVP 取舍（用户未最终拍板） |
   |---|---|---|
   | 自信地错 | 核验闭环 | 先做死 |
   | 答非所问 | 口径澄清 | 先做死 |
   | 链条断裂 | 失败恢复 | 简单版（重试上限） |
   | 失控消耗 | 成本控制 | 简单版（次数预算） |
   | token 爆/注意力散 | 上下文管理 | 最简（文件存中间结果） |
   - 关键判断：**五项不靠模型智商，靠架构设计**——便宜模型+好架构 > 强模型+裸奔
6. **数据感知三层**（用户提出「大数据怎么知全貌、了解不够怎么补」）：
   - **机械画像**（代码）：profile 卡片——shape/列/类型/缺失/describe/nunique/head，百万行压成几百 token，LLM 读卡片不读数据
   - **语义解读**（LLM）：机器猜列含义（主键/外键/口径疑似问题），产出语义层理解
   - **人为补充**（**数据字典文件**，不在对话里临时补）：YAML 一次写好长期复用，含含义/口径/坑；理由=持久+算前带口径意识+作品亮点（人对 AI 的知识输入工程化）
   - 分工：画像自动做、语义机器猜人审、**口径和坑永远人说了算**

## 追加（同日第二轮）：黑板模式与审批门

1. **用户提出交互形态**：大量重复迭代的数据工作需要「确定性黑板」——可观察、可随时调整的记事本，记两表连接映射等决策；且必须给数据人明确展示，不只给 Agent 看 → 黑板模式（Blackboard），与普通 Agent 记忆的分界线就在「人可读可改」
2. **三层记忆确立**：对话记忆（会话级）／黑板（项目级，Agent写待确认区+人改已定区）／字典（跨项目，人写）。字典=事实，黑板=决策（每条挂 why）
3. **用户 Jupyter 类比**：工作单元=单元格，方便回溯反复推敲 → steps/ 设计原则：每格=决策+代码+产出三合一，产出落盘、下游从盘读（避免 notebook 隐藏状态陷阱）；notebook 记不住 why，黑板补上决策层。三层分工：steps 管执行／黑板管决策／字典管事实，回溯链路闭合
4. **用户推出确定性边界**：LLM 本身不确定，黑板上的东西必须确定可执行可回溯 → 需要标准审批门。理论依据=「LLM 输出生成时只是提案，跨审批门才成事实」，与三层记忆的写权限设计同源
5. **我方纠正**：「是否修改原数据」按钮不应存在——原数据物理只读，连审批过的修改都不允许（审批防 LLM 不确定，防不了审批误判；基准不可破）。正确模式=衍生品：原数据只读+每步产出独立副本+改决策=改黑板删下游重跑
6. **我方纠偏规模认知**：全部组件（目录约定+markdown+审批提示+写入白名单+ReAct骨架）几百行代码，庞大感来自提前产品化。43 课交付=能演示完整闭环的小流程 MVP，不是平台
7. 43 课设计拼图累计五块：感知三层 → 五项必备能力 → 三大产品级要求 → 三层记忆 → **确定性边界+审批门+原数据不可变**
