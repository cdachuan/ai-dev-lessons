## 核心内容

1. **原理**：pandasai 不是新分析库，是给 pandas 加「翻译层」——大模型把中文问题翻译成 pandas/SQL 代码 → 本机执行 → 返回数字/表格/图表
2. **体验路径**（v3 API）：`pip install pandasai` + `pandasai-litellm`（要求 Python 3.8–3.11，用户 3.11 ✓）→ 配 LLM（key 走环境变量）→ `pai.read_csv()` → `df.chat("问题")`
3. **三类坑**：不懂口径（退款算进销售额）、列名/字段幻觉、生成的代码有 bug——共同点：都不报错，安静地给错数字
4. **把关清单三步**：要代码 → 对口径（31 课三问）→ 自己复算
5. **判断框架**：✅探索性快问快答/给非技术同事自助查数/快速画趋势；❌正式汇报口径/敏感数据外传红线/自己看不懂答案的场景
6. **伏笔**：pandasai 本质 =「会写 pandas 的 Agent 雏形」（LLM 想 + 工具算），衔接 34 课亲手搭 Agent+数分

## 关键设计点

- **主线延续 31 课**：「Pandas 会写 ≠ 能回答业务问题」升级为「AI 给的数 ≠ 能写进汇报的数——中间隔着你的 pandas 眼睛」
- **红线提醒**：问题会发给外部大模型，公司真实业务数据不外喂（呼应数据边界规矩），练习用模拟 orders.csv
- **版本防坑**：标注老教程 SmartDataframe 是 v2 写法，v3 入口是 pai.read_csv + .chat()；LiteLLM 为统一接口可换模型，细节以官方文档为准不写死参数

## 小测

pandasai 返回「数码类目销售额最高，共 4598 元」，写进汇报前最该做什么？

- A. 让它再画一张图表
- B. 核验它生成的代码和口径 ✓
- C. 换更大的模型重新问
- D. 检查电脑内存

正确答案 **B**。主线即「翻译层不可信，你得把关」；A 错在源头数字错则图更隐蔽，C 错在换模型是提命中率不是核验手段。教训：先要代码、对口径、复算三关过了才轮得到汇报。
