## 核心内容

1. **从「能跑」到「能跑稳」的 3 个新问题**：AI 传错参数、返回格式混乱、AI 该调不调/不该调乱调
2. **武器 1：参数校验**——AI 传错就拦下来，**不抛异常**而是**返回错误结构**，让 AI 看到后自己重试
3. **武器 2：统一返回格式**——永远 `{"ok": True/False, "data"/"error"}`，AI 不用记每个工具的返回类型
4. **武器 3：好 description**——4 条铁律：输入是什么、输出是什么、何时该用、何时不该用（给反例）
5. **JSON Schema 的 `pattern`**：软约束，大模型尽量遵守但不保证，**函数内校验是硬约束**（双重保护）
6. **完整工具模板**：`_ok(data)` / `_err(msg)` 两个辅助函数 + 参数校验 + try/except + 4 条铁律 description

## 关键设计点

- **错误信息要让 AI 能读懂**：抛异常会打断 ReAct 循环，返回错误结构反而让 AI 看到后自动重试
- **统一返回格式的好处**：AI 不用记每个工具的返回形状——新会话也不丢；代码统一处理，不用 if-elif
- **description 是 AI 决策的唯一依据**：函数名只用于关键词匹配，函数代码 AI 看不到
- **Schema 软约束 + 函数硬约束**：缺一不可。Schema 帮 AI 知道格式，函数保命
- **工具不是越多越好**：4-8 个是合理区间，多了 AI 反而更纠结

## 小测

想让 AI 在多个工具中**减少选错工具**的概率，最关键应该改：

- A. 把工具函数名改得更短
- B. 在 description 里写清「何时用、何时不用」并给反例 ✓
- C. 工具数量越多越好，AI 选的可能性就多
- D. 把 description 改成英文，更专业

正确答案 **B**。description 是 AI 选工具的唯一依据，写清「何时用」+「何时不用」是核心。

A 错：函数名长短对 AI 决策影响很小，description 才是关键。
C 错：工具不是越多越好，4-8 个是合理区间。
D 错：DeepSeek / GPT 中文理解能力很好，中文 description 在中文场景下反而比英文更准。

## 教学设计

- **承接 29 课的「wttr.in 工具」**：把那个工具的 description / 返回值 / 校验改造一遍就是本课练习
- **三个武器层次清晰**：参数校验（输入层）→ 统一格式（输出层）→ 好 description（决策层）
- **错误结构 vs 异常**：这是 Agent 工程化和普通程序设计最大的区别——**故意不抛异常**
- **不引入 JSON Schema 校验库**（如 jsonschema）：保持轻量，**重点是设计原则不是工具库**
