## 核心内容

1. **工作流 ≠ Agent**（根本区别，出自 Anthropic 权威文档）：
   - 工作流 Workflow = 路径由开发者代码预先定好，模型只做单点判断；可预测性高、适合要稳定/便宜/审计
   - Agent = 路径由模型边做边定，代码提供工具；低可预测，适合路径说不清、需临场判断
2. **五种经典工作流结构**（覆盖几乎所有「看起来像 Agent」的重复任务）：
   - 提示链 / 路由 / 并行 / 编排者-执行者 / 评估者-优化者
   - 第5种（评估者-优化者）就是 34 课 verify 核验思想的同构——不陌生，只是现在有了名字可以主动选
3. **判断规则（本课最该记住的表）**：步骤固定/要审计/要复现/成本敏感/是把已知步骤拼起来 → 写死成工作流；只有需要语义判断 → 放手给 Agent
4. **最常见的过度设计**：用 Agent 干工作流的活。例：「读Excel→算5指标→填模板→发出」是固定流程，定时脚本就是正解，硬做 Agent 会每次跑法不同/难排查/token翻倍
5. **拆任务四步法**（动手前先在纸上做）：写现状步骤 → 逐步贴 [确定]/[需判断] 标签 → 各归各位（[确定]=工具函数，[需判断]=交模型）→ 标出核验点挂 verify
6. **反直觉结论**：[需判断] 的步骤往往只有 1-2 个（通常是「听懂问题」和「组织结论」），中间一大段是 [确定]。→ Agent 大部分代码应是普通 Python，模型只在关键处出手——呼应 09-02「便宜模型+好架构 > 强模型+裸奔」
7. **控制上下文两招**：中间产物落盘（对话只留「已存到 XXX」）/ 画像代替全量数据（前3行+行数列数类型，如 profile 工具）——37 课项目已各用一半

## 关键设计点

- **37→38 无硬依赖**：37 是可动手的项目课，38 是概念架构课；教材明确「无需新代码，动手任务是对 37 项目贴标签」，降低启动阻力
- **区分工作流 vs Agent 是本课核心心智**：不是「越智能越好」，而是「会划线」——线内写死（确定/可复现/便宜），线外交给模型
- **与求职定位对齐**：面试能讲「我知道哪些步骤该写死、哪些该让模型判断」= 工程判断力，这是区分「会调 API」与「会做系统」的话术

## 小测

题目：做「每周一自动生成上周销售周报」（读上周数据→算6个固定指标→按模板生成→发群），用什么方式最合适？
**答案 B**：固定流程脚本 + 需要判断处单独调一次模型。指标固定且答案唯一，用代码写死最稳省——A 错在把确定性步骤变不确定（口径不一致）；C 错在 6 指标是无谓并行化；D 错在让模型算多步聚合（算不准），数字必须由代码算，模型只解释数字（呼应 19/34 课那条线）。
