## 核心内容

1. **破除神秘感**：部署不是更高深的技术，而是把三件「脑子里有、没写下来」的事写进文件——**依赖说清、密钥分离、入口明确**
2. **四大交付坑**（诊断表）：依赖没写（ModuleNotFoundError）／密钥混在代码里／绝对路径写死（别人机器上不存在）／数据没跟着走（或真实数据进了仓库）
3. **三级阶梯**（按成本从低到高，不许跳级）：
   - 阶梯 0 · **可复现仓库**（0 元，当天可完成）：README + requirements.txt + .env.example + .gitignore + 示例数据 + 入口脚本。求职价值最高的一级
   - 阶梯 1 · **免费托管**（Streamlit Community Cloud）：GitHub 登录→选仓库/分支/入口→Deploy，git push 自动更新；key 放平台 Secrets，代码用 `st.secrets` 读。⚠️ 国内网络可访问性需本人实测后再写进简历
   - 阶梯 2 · **国内云**：阿里云函数计算 FC「Web 函数」／腾讯云 Serverless HTTP（按量计费，不用不计费，新账号有试用额度）／轻量应用服务器（百元级年起）。本课只认路不实操
4. **六条检查清单**：依赖写全、key 不写死、无绝对路径、示例数据随仓库、README 第一行是启动命令、**「假装自己是别人」换目录跑一遍**

## 关键设计点

- **顺延规则复用**：35 课 09-08 推送、09-09/09-10 两次提醒无响应 → 09-11 按 19/20/30 课先例兜底标记 done，同晚推送 36，不空转不丢课
- **求职锚点**：阶梯 0 明确标注「对求职价值最高」——面试官认「我 clone 下来跑通了」，比自我描述硬
- **安全线延续**：35 课安全闸①（key 环境变量）在本课升级为「交付必须」；`.env` 进 `.gitignore`、真实业务数据绝不进仓库
- **不为部署而部署**：明确「先用 0 元方案跑通全流程，缺什么再补什么，别一上来买服务器」
