## 核心内容

1. **自建数分 Agent 与 pandasai 的分水岭**：核验卡口（口径声明 + 复算）。「想算分离」两者相同，差的是一道卡口
2. **感知三层**：① 机械画像（代码，60 行压成 717 字符卡片）② 语义解读（LLM 猜，人审）③ 人为补充（数据字典，留到 43 课）
3. **三个工具**：`data_profile`（画像）/ `analyze`（分组聚合 + 返回口径字段）/ `make_bar`（pyecharts 落盘）
4. **核验是内置步骤不是可选后缀**；中间产物（卡片/口径/结果/图）留痕可回溯
5. **三大产品级要求**（32 课探讨产出）本课做进前两条：核验内置、产物可见；第三条「敢说不知道」等 35/43 课

## 关键设计点

- **分工铁律**：画像自动做、语义机器猜人审、口径和坑永远人说了算
- **口径跟结果一起返回**：`analyze` 返回值 `{"口径": ..., "结果": ...}`，报数必带口径
- **复算是人的卡口**：Agent 报数后自己手写一遍对账
- **反直觉提醒**：自建 Agent 兜底逻辑全自己写，漏了验证反而「错得更自信」——核验是保命绳不是锦上添花

## 实测数据（已实跑验证，orders_60.csv）

- 60 行、4 品类、46 已完成 / 14 已退款
- 各品类已完成销售额：数码 9932 / 服饰 9838 / 食品 6660 / 家居 6194，合计 32624
- 不过滤退款直接算 = 39670 → **口径差一个条件，数字差 7046**（本课核心例证）
- profile 卡片 717 字符（60 行数据压成几百 token）
- 工具函数全部本地跑通（pandas 2.3.3 / pyecharts 2.1.0 / openpyxl）

## 小测

数分 Agent 每次报数都被领导追问口径。最能根治的是：**C**——把「口径声明 + 复算」做成 analyze 的默认输出。

（A 换更贵模型只提升「想」的命中率非核验；B 工具更多≠更可靠；D 把口径变可选正是要消灭的坏习惯）
