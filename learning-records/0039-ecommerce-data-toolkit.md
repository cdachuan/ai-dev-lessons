## 核心内容

1. **为什么封装成工具而非散写脚本**：读一次复用多次、口径显式传参可见、结构化错误精确定位、函数签名+docstring 就是 Agent 的说明书
2. **工具设计四要素（缺一不可）**：
   - 工具描述（docstring 写给 Agent 看：用途/参数含义/调用时机/口径）
   - 参数设计（显式、直白、带默认值，Agent 不用猜）
   - 结构化返回（字典，不 print、不返回 DataFrame）
   - 错误反馈（异常时返回有意义信息，不静默失败）
3. **关键认知**：工具的「说明书」是给大模型看的——模型靠函数名/参数名/docstring 决定调哪个工具传什么参 → 好工具=好 API 设计
